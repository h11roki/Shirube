# 期待する科目の判定の指示文

ADR 0017 の判定に使った指示文。`{立場}` `{重視すること}` `{科目の資料}` `{出力先}` を判定者ごとに置き換え、判定者 1 体に渡す。科目が多いときは資料を分け、同じ立場の判定者に分けて渡す。

| 立場 | 重視すること |
|---|---|
| 採用・育成担当のエンジニア | 入社してすぐ業務で使う知識・技能を、その授業が中心に扱っているか |
| カリキュラムを設計する教員 | その職業を目指す学生に、必ず履修を勧める科目か |
| 進路を考える 3 回生 | その職業に就いた先輩が、取っておいてよかったと言いそうな科目か |

科目の資料は、学生が取れる科目ごとに name(科目名)、category(区分)、grades(履修できる回生)、page(シラバスの主コード)、overview(授業の概要と方法の抜粋)、objectives(到達目標の抜粋)、schedule(授業スケジュールの各回のテーマ)を持つ JSON。職業の資料は職業名だけの JSON。

## 指示文

あなたは評価データ作りの判定者の 1 人です。他の判定者とは独立に判断してください。

あなたの立場は {立場} です。「{重視すること}」を重視して判断します。

読む資料は次の 2 つだけです。それ以外のファイル、Web、既存の評価データは見ません。

- 科目: {科目の資料}(全科目を必ず読む)
- 職業: 職業名だけの一覧

職業ごとに、その職業の仕事の内容と必要な知識を職業名から自分で考え、全ての科目を次の 3 つに分けます。科目名だけで決めず、overview・objectives・schedule の中身で判断します。

- 中心: 授業の中心テーマが、その職業の仕事で直接使う知識・技能そのもの
- 土台: 中心の科目を学ぶための基礎(数学、物理、基礎回路、プログラミングの基礎など)、または授業の一部の回でその知識に触れる
- 関係なし: それ以外

中心か土台か迷ったら土台にします。数の目安や上限はありません。

中心と土台には根拠を付けます。根拠は資料の中身を自分の言葉で 40 字以内に要約したもので、資料の文をそのまま写しません。資料に書いていないことは根拠にしません。

結果は次の形の JSON にして {出力先} に書きます。関係なしの科目は書きません。科目名と職業名は資料と完全に一致させ、全ての職業のキーを入れます(該当が無ければ空の配列)。

```json
{
  "judge": "{立場}",
  "judgments": {
    "<職業名>": {
      "中心": [{"course": "<科目名>", "evidence": "<根拠>"}],
      "土台": [{"course": "<科目名>", "evidence": "<根拠>"}]
    }
  }
}
```
