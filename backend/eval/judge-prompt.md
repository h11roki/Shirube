# 期待する科目の判定の指示文

ADR 0017 の判定で判定者に渡した指示文。`{立場}` `{重視すること}` `{学科}` `{科目の資料}` `{科目数}` `{職業の資料}` `{職業数}` `{出力先}` を判定者ごとに置き換え、Claude Code のサブエージェント 1 体に渡した。科目は名前順に前半と後半に分け、同じ立場の判定者 2 体に 1 つずつ渡した。

資料作りと集計は `python -m app.presentation.cli.judging` で行う(ADR 0054)。`materials --out <dir>` が、評価データにあって判定に無い職業について、科目の前半(`courses-1.json`)と後半(`courses-2.json`)と職業名(`occupations.json`)を書く。判定者の出力は `merge --first <前半の 3 つ> --second <後半の 3 つ> --materials <dir>` でまとめ、中心が 1 票だけの科目は高橋さんの決定を `--decisions <JSON>`(職業名から科目名と core か foundation への対応)で渡す。`expected` は全ての職業の期待する科目を判定から作り直すだけ。

| 立場 | 重視すること |
|---|---|
| 採用・育成担当のエンジニア | 入社してすぐ業務で使う知識・技能を、その授業が中心に扱っているか |
| カリキュラムを設計する教員 | その職業を目指す学生に、必ず履修を勧める科目か |
| 進路を考える 3 回生 | その職業に就いた先輩が、取っておいてよかったと言いそうな科目か |

## 資料

科目の資料は、検索の候補の科目名ごとに 1 件の JSON。

- name: 科目名。category: 区分(その科目名の授業の区分を「・」でつないだもの)。grades: その学科の学生がその年度に履修できる回生
- page: 使ったシラバスの主コード。同じ科目名に複数のクラスがあるときは、その学科向けのクラス(無ければ最初のクラス)のシラバス
- overview: 授業の概要と方法の先頭 450 字。objectives: 到達目標の先頭 250 字。schedule: 授業スケジュールの各回のテーマ(空のテーマは除く)を「、」でつないだ先頭 350 字。どれも空白と改行は 1 つの空白にまとめる

職業の資料は、判定する職業名だけを並べた JSON。

2026 年度の判定では、{学科} は「立命館大学 理工学部 電子情報工学科」、{科目数} は 94、{職業数} は 10(ADR 0054 で足した 2 回目は 20)。

## まとめ方

判定者の出力を `judgments.json` にまとめ、そこから `occupations.json` の期待する科目を作る(`judging merge` が行う)。期待する科目が 1 つも無い職業は、再現率を測れないので評価データに入れない。

- 前半と後半の判定を立場ごとに合わせる。中心は core、土台は foundation とし、関係なしの科目は書かない。判定者に渡した前半と後半の科目名は parts に残す
- 2 体以上が core の科目を期待する科目にする。1 体だけが core の科目は高橋さんが決め、decision に core か foundation を書く
- 期待する科目の理由は、core とした判定者の根拠を教員、3 回生、エンジニアの順で先にあるものから取る
- 期待する科目は core の票が多い順、同じ票数なら科目名の順に並べる

## 指示文

あなたは評価データ作りの判定者の 1 人です。他の判定者とは独立に判断してください。

あなたの立場は {立場} です。「{重視すること}」を重視して判断します。

読む資料は次の 2 つだけです。それ以外のファイル(リポジトリ、既存の評価データなど)と Web は見ません。

- 科目: {科目の資料}
  {学科}の学生が取れる科目の一部({科目数} 科目)。科目ごとに name、category、grades、page、overview、objectives、schedule がある。大きいので Read の allow_large を使うか offset と limit で分けて、全 {科目数} 科目を必ず読む。
- 職業: {職業の資料}(職業名だけの一覧、{職業数} 職業)

職業ごとに、その職業の仕事の内容と必要な知識を職業名から自分で考え、全ての科目を次の 3 つに分けます。科目名だけで決めず、overview・objectives・schedule の中身で判断します。

- 中心: 授業の中心テーマが、その職業の仕事で直接使う知識・技能そのもの
- 土台: 中心の科目を学ぶための基礎(数学、物理、基礎回路、プログラミングの基礎など)、または授業の一部の回でその知識に触れる
- 関係なし: それ以外

中心か土台か迷ったら土台にします。数の目安や上限はありません。

中心と土台には根拠を付けます。根拠は資料の中身を自分の言葉で 40 字以内に要約したもので、資料の文をそのまま写しません。資料に書いていないことは根拠にしません。

結果は次の形の JSON にして {出力先} に Write ツールで書きます。関係なしの科目は書きません。科目名と職業名は資料と完全に一致させ、{職業数} 職業全てのキーを入れます(該当が無ければ空の配列)。書いたら python3 で json.load できるか確かめます。

```json
{
  "judge": "{立場}",
  "judgments": {
    "<職業名>": {
      "中心": [{"course": "<科目名>", "evidence": "<根拠>"}],
      "土台": [{"course": "<科目名>", "evidence": "<根拠>"}]
    }
  }
}
```

最後の返答は、職業ごとの中心と土台の件数の一覧だけにします。
