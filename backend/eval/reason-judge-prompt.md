# 理由の文の判定の指示文

ADR 0088 の正解作りで判定者に渡した指示文。`{理由の資料}` `{理由数}` `{出力先}` を置き換え、Claude Code のサブエージェント 3 体に同じ文を 1 体ずつ渡した。立場は分けない。

資料作りと集計は `python -m app.presentation.cli.reason_judging` で行う。`sample <実験の結果の JSON> --out <dir>` が、結果の 1 回目の推薦の理由(道標に並ぶ柱と礎。中心につながらず外した礎は除く)から判定する理由を取り出し、`<dir>/reasons.json` に混ぜた順で書く。`merge <実験の結果の JSON> --votes <判定者の出力 3 つ> --model <判定者のモデル> --out <書く先>` が、同じ結果から同じ理由を取り直して判定者の出力と突き合わせてまとめる(残した正解を黙って上書きしないよう、書く先は毎回書く)。`check <実験の結果の JSON>` が、`reason-judgments.json` がその結果から取り直した理由と合うかを確かめ、正解の段の数と 3 体の一致を出す。確かめ用の職業(ADR 0067)の入った結果は断る。2026-11-04 の正解は `--model "Claude Opus 5.5(Claude Code のサブエージェント)" --out eval/reason-judgments.json` でまとめた。

## 取り出し方

- 職業を名前の順に並べ、乱数(種 0)で混ぜて、前の 25 職業を整える用、後ろの 25 職業を確かめる用にする。同じ職業の理由は似るので、件ではなく職業で分ける
- 整える用と確かめる用のそれぞれから、柱の理由を 38 件、礎の理由を 37 件、別の乱数(種 `0 reasons`)で取る
- 150 件を同じ乱数で混ぜ、r001 から番号を振る。判定者には、整える用か確かめる用かを渡さない

2026-11-04 の正解は、今の本番と同じ設定の `eval/runs/20261031-120812-selection-min-votes-before.json`(開発用 50 職業、1 回)から作った。{理由数} は 150。

## 資料

理由ごとに 1 件の JSON。

- id: 理由の番号
- occupation: 選び手に渡した職業(職業名を読み取った解釈)。assumption: 解釈の前提(無ければ null)
- kind: 柱(職業の仕事で直接使う授業)か礎(柱の授業の前提になる授業)
- course: 授業名。pillar: 礎のとき、その礎が前提になる柱の授業名(柱なら null)
- reason: 選び手が書いた理由の文。学生は切符でこれを読む

## まとめ方

- 3 体の票の中央値(無い < ぼんやり < 具体的)を正解にする。2 票がそろえばその段、3 票が割れればぼんやりになる
- 3 体どうしの一致は、柱と礎それぞれで Fleiss の κ を出す

## 指示文

あなたは、大学の授業を薦めるアプリが書いた「取るべき理由」の文を判定する判定者の 1 人です。他の判定者とは独立に判断してください。

読む資料は {理由の資料} だけです({理由数} 件)。それ以外のファイル(リポジトリ、評価データ、シラバスなど)と Web は見ません。

アプリは、なりたい職業を入れた学生に、授業を「柱」と「礎」に分けて薦め、授業ごとに理由の文を付けます。

- 柱: その職業の仕事で直接使う知識や技能を学ぶ授業
- 礎: 柱の授業を学ぶ前提になる授業。どの柱の前提かが pillar にある

理由の文が、次の決まりのどの段に当たるかを判定します。柱と礎で、見ることが違います。

柱の理由は「職業とのつながり」を見ます。

- 具体的: 職業の仕事の中身(する作業、作るもの、扱う対象、使う技能)を 1 つ以上挙げ、授業で学ぶことがそこにどう使われるかが分かる
- ぼんやり: 職業や分野、「実務」「業務」には触れるが、「役立つ」「直結する」「必須」「基礎になる」だけで、仕事のどこにどう使うかが分からない
- 無い: 授業で学ぶことの紹介だけで、職業にも仕事にも触れていない。授業で身につく技能を挙げるだけで、職業の仕事に結び付けていないものも無いにする

礎の理由は「柱の前提」を見ます。

- 具体的: つながる柱の授業(科目名か、その授業で扱う内容)を挙げ、この授業のどの内容が、柱のどの内容の前提になるかが分かる
- ぼんやり: 柱の授業や分野には触れるが、「基礎になる」「理解に役立つ」だけで、柱のどの内容の前提かが分からない
- 無い: 柱の授業にも、その内容にも触れていない。職業に触れるだけのものも無いにする

例(資料には無い、作った例です。職業は「鉄道の運行管理システムのエンジニア」、柱は「待ち行列理論」、礎は「確率論入門」で、礎は「待ち行列理論」の前提とします)

| 段 | 柱「待ち行列理論」の理由 | 礎「確率論入門」の理由 |
|---|---|---|
| 具体的 | 到着と待ちの確率モデルを学び、列車の遅れが駅や路線へ広がる様子を見積もって運行計画を検討するのに使える | 確率変数と指数分布を学び、待ち行列理論で到着の間隔と待ち時間の分布を扱う前提になる |
| ぼんやり | 待ち行列のモデルを学び、運行管理システムの開発の実務に直結する | 確率の基礎を学び、待ち行列理論の理解に役立つ |
| 無い | 到着の分布と待ち時間の求め方を、演習で計算して身につける | 確率の考え方を身につけ、運行管理の仕事に役立つ |

次のことは判定に入れません。

- 理由の中身が事実か(授業で本当に扱うか)
- 文の長さ、言い回しの上手さ、誤字
- その授業を薦めたこと自体の良し悪し
- 他の理由との比べ(段の数をそろえようとしない)

理由ごとに、まず根拠を 60 字以内で書き、そのあと段を決めます。根拠には、職業の仕事の中身(柱)か柱の内容(礎)として何を挙げているか、または何が無いかを書きます。

結果は次の形の JSON にして {出力先} に Write ツールで書きます。grade は specific(具体的)、vague(ぼんやり)、absent(無い)のどれかです。資料の {理由数} 件全てについて、資料と同じ id で 1 件ずつ書きます。書いたら python3 で json.load でき、件数が {理由数} で id に重なりが無いかを確かめます。

```json
{
  "grades": [
    {"id": "r001", "why": "<根拠>", "grade": "specific"}
  ]
}
```

最後の返答は、柱と礎それぞれの specific、vague、absent の件数だけにします。
