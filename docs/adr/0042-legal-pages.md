# 0042. プライバシーポリシーと利用規約を画面に置き、ログインで同意したとみなす

- ステータス: 承認
- 日付: 2026-10-22

## 文脈

本番は誰でも Google でログインして使える公開にする(ADR 0038)。保存するのは Google の利用者の番号(sub)、入力した職業と回生と学科、作った道標、もう取ったと答えた授業で、道標を作るときに職業名などを OpenAI の API に送る。道標の削除と退会は ADR 0041 で作った。利用者に、何を保存し、どこへ送り、どう消せるかを示すプライバシーポリシーと、大学とは関係のない非公式のアプリであることと責任の範囲を示す利用規約が要る。問い合わせ先は本名とメールアドレスを出さず、ハンドル名(h11roki)と GitHub の Issue にする(本番の前の点検で決めた)。

シラバス取得の User-Agent には職場のメールアドレスが入ったまま公開リポジトリにあり、ポリシーの問い合わせ先とそろえる必要がある。

## 検討した選択肢

同意の取り方

1. Google でログインのボタンの下に「ログインすると利用規約とプライバシーポリシーに同意したことになります」と書き、ログインで同意したとみなす
2. 初回のログインのあとに同意の画面を出し、users 表に同意した版と日時を記録する

文書の置き場

1. frontend のページ(`/privacy`、`/terms`)に書き、共通の部品で同じ体裁にする
2. `docs/` の Markdown を取り込んで描く(Markdown の描画の依存が増え、`docs/` は開発者向けの文書と混ざる)

準拠法と裁判所

1. 準拠法は日本法と書き、裁判所は書かない
2. 準拠法は日本法、専属的合意管轄は京都地方裁判所
3. どちらも書かない

User-Agent の連絡先

1. リポジトリの URL だけにする
2. 個人のメールアドレスに置き換える
3. 今のまま

## 決定

高橋さんが選んだ。同意は 1(ログインでみなす)、置き場は 1(frontend のページ)、準拠法は 1(日本法、裁判所は書かない)、User-Agent は 1(リポジトリの URL だけ)。

- プライバシーポリシー(`/privacy`)に書くこと: 運営者は個人(h11roki)で問い合わせは GitHub の Issue。保存するのは Google の sub、入力(職業、回生、学科、クラスの選択)、道標、もう取ったと答えた授業。Google から受け取る名前とメールアドレスとプロフィール画像はサーバーに保存せず、ログイン状態を保つ暗号化したクッキーにだけ置く。外部へ送るのは、Google(ログイン)と OpenAI の API(職業名と、そこから読み取った職業とスキル、シラバスの抜粋。利用者を特定する情報は送らない)。クッキーは Auth.js のもの、localStorage は見た目の設定。サーバーのログにはアクセスログ(IP アドレス、時刻、URL、状態コード)とアプリのログ(道標の番号、状態、失敗の原因。失敗の原因には職業名が含まれることがある)を残し、障害の調査に必要な期間だけ残して古いものから消す(期間の数字は、本番化でログの回転を実装するときに決めて書き足す)。消し方は道標ごとの削除(作っている途中の道標はできてから。入力した内容も道標と一緒に消える。その日に作った道標は、作った日時と誰が作ったかだけが翌日の 0 時まで残る)と退会(その日に作った道標の日時だけが誰のものか分からない形で残る)(ADR 0041)。改定は日付を付けてこのページで知らせる
- 利用規約(`/terms`)に書くこと: 立命館大学とは関係のない個人の非公式のアプリであること。シラバスと時間割表の内容の権利は大学にあり、短い引用と原ページへのリンクにとどめること。道標は参考で、必修、卒業要件、抽選、時間割の変更を見ておらず、AI の出力で誤りがあること。履修は大学の正式な情報で確かめること。1 日の作成の上限などサービスの維持のための制限。禁止事項(他人のアカウントの利用、過度な負荷、攻撃、AI に目的の外のことをさせる入力、法令に反する利用)。サービスの変更と停止、終わるときはページで知らせてからデータを消すこと。免責(現状有姿、法令が許す範囲で責任を負わない)。準拠法は日本法。改定の知らせ方。問い合わせ先
- 全てのページの下にフッターを置き、非公式の断り、利用規約、プライバシーポリシー、GitHub(ソースコードと問い合わせ)へのリンクを出す
- ログインのボタンは同意の文と組にし、入力の画面の紹介と、ログインが要る画面の案内に置く(同意の文の無いボタンを残さない)。ヘッダーのログインは、同意の文つきのボタンを置いたログインのページ(`/login`)へのリンクにする
- シラバス取得の User-Agent は `shirube/0.1 (+https://github.com/h11roki/Shirube)`

## 理由

- 同意の画面と記録は、表と API と画面が増えて 1 PR 分になるが、個人の無料アプリで規約の改定に再同意を求める場面は当面ない。ログインのボタンの下に書けば、ログインする人は必ず目にする
- 文書は画面のページに直接書けば依存が増えず、見た目もほかの画面とそろう
- 裁判所まで決めるのは学生の個人開発には重く、準拠法だけで争いのときの基準は示せる
- 連絡先をポリシーと同じ GitHub にそろえれば、職場のメールアドレスを公開リポジトリから外せる

## 受け入れたトレードオフ

- 同意した日時は残らない。改定は文書の日付で示し、使い続ければ同意したとみなす
- 争いのときの裁判所は法律の既定に従う
- 大学などからの連絡はメールでなく GitHub の Issue で受ける
- ログの保存期間は、本番化(ADR 0009 の見直し)でログの回転を実装するときに決め、ポリシーに数字を書き足す。それまでポリシーは「必要な期間だけ残して古いものから消す」とだけ書く

## 再検討する条件

- 規約の改定で再同意が要るほど利用者が増えたとき(同意の画面と記録を足す)
- 大学から連絡の手段や取得の方法について求めがあったとき
- 他大学に広げて運営の形が変わるとき
