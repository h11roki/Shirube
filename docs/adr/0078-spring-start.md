# 0078. 始める学期を省いたときは、入力した回生の春学期から組む

- ステータス: 承認
- 日付: 2026-10-31

## 文脈

- ADR 0029 で、始める学期を省いたときは今日の月から決める(4〜8 月は春学期、9〜3 月は秋学期)と決めた。秋学期の履修登録がある 9 月からは、秋学期を計画したい利用者が多いと見ていた
- 本番を出して高橋さんが使ったところ、10 月に開くと既定が秋学期になり、入力した回生の 1 年が半分しか出ず、おかしく見えた
- 入力の画面は、始める学期を選べる。選ばなければ、クラスの選択の API(`GET /api/v1/class-choices`)が決めた学期を返し、画面はそれを出して送り返す(ADR 0030)

## 検討した選択肢

- いつも入力した回生の春学期から組む
- 次の春学期から組む(10〜3 月なら来年度の春で、回生も 1 つ上げる)
- 今のまま、今日の月から決める

## 決定

高橋さんが、いつも入力した回生の春学期から組むことを選んだ。

- 道標の API、クラスの選択の API、CLI の `plan create` は、始める学期を省けば春学期にする。既定は domain の `DEFAULT_START_TERM` の 1 つに置く
- 日付から学期を決める関数(`term_on`)と、それだけに使っていた API への今日の日付の受け渡しは消す
- 入力の画面は、クラスの選択の答えが届く前の学期の欄を「既定の学期」と出す。春学期という決まりは backend だけが持つ

## 理由

- 入力した回生の 1 年が丸ごと出るので、道標として読みやすい
- 次の春学期から組む案は、これから履修を決める学期から出せるが、回生の欄が今の回生か来年度の回生かで迷いやすく、4 回生の秋学期のあとが無いなど決めることが増える
- すでに過ぎた春学期の授業は、結果の画面で「もう取った」と答えれば外せる(ADR 0034)

## 受け入れたトレードオフ

- 秋学期に使う人は、すでに過ぎた春学期から組まれる。秋学期から組みたいときは、始める学期で秋学期を選ぶ
- 秋学期に作った道標で、前の学期に開講された授業を「もう取った」と聞く場面が減る(春学期から始めると、前の学期が無い)

## 再検討する条件

- 秋学期に使う人が、毎回秋学期を選び直していると分かったとき
