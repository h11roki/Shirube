# 0078. 始める学期を省いたときは、入力した回生の春学期から組む

- ステータス: 承認
- 日付: 2026-10-31

## 文脈

- ADR 0029 で、始める学期を省いたときは今日の月から決める(4〜8 月は春学期、9〜3 月は秋学期)と決めた。秋学期の履修登録がある 9 月からは、秋学期を計画したい利用者が多いと見ていた
- 本番を出して高橋さんが使ったところ、10 月に開くと入力の画面の「始める学期」の 2 択の初期値が秋学期になり、そのたびに春学期へ選び直すのが不自然だった。入力した回生の 1 年も半分しか出ない
- 「もう取った」で聞くのは、始める学期より前の学期に開講された推薦の授業だけで、始める学期に置いた授業は聞かない(ADR 0034)
- 入力の画面は、始める学期を選べる。選ばなければ、クラスの選択の API(`GET /api/v1/class-choices`)が決めた学期を返し、画面はそれを出して送り返す(ADR 0030)

## 検討した選択肢

- いつも入力した回生の春学期から組む
- 次の春学期から組む(10〜3 月なら来年度の春で、回生も 1 つ上げる)
- 今のまま、今日の月から決める

## 決定

高橋さんが、いつも入力した回生の春学期から組むことを選んだ。

- 道標の API、クラスの選択の API、CLI の `plan create` は、始める学期を省けば春学期にする。既定は domain の `DEFAULT_START_TERM` の 1 つに置く。クラスの選択の API はクエリの既定にして OpenAPI にも載せる。道標の API の本文は、省けるまま受けて既定を当てる(openapi-typescript が既定のある欄を必須の型にし、クラスの選択を読めなかった画面が学期なしで送れなくなるため)
- 日付から学期を決める関数(`term_on`)と、それだけに使っていた API への今日の日付の受け渡しは消す
- 入力の画面は、クラスの選択の答えが届く前の学期の欄を「既定の学期」と出す。春学期という決まりは backend だけが持つ

## 理由

- 入力の画面の 2 択の初期値が春学期になり、選び直さずに済む。入力した回生の 1 年が丸ごと出るので、道標として読みやすい
- 次の春学期から組む案は、これから履修を決める学期から出せるが、回生の欄が今の回生か来年度の回生かで迷いやすく、4 回生の秋学期のあとが無いなど決めることが増える

## 受け入れたトレードオフ

- 秋学期に既定のまま作ると、もう終わった春学期から組まれる。その学期に置かれた授業は、取っていなくても「もう取った」で外せず、その学期の単位の枠も使う。秋学期から組みたいときは、始める学期で秋学期を選ぶ

## 再検討する条件

- 秋学期に使う人が、毎回秋学期を選び直していると分かったとき
