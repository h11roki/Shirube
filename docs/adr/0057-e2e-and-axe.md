# 0057. 画面の通しの試験を Playwright で本番ビルドに対して流し、axe で WCAG 2.2 の A と AA の違反を CI で落とす

- ステータス: 承認
- 日付: 2026-10-24

## 文脈

品質の点検で決めたテーマ A〜I のうち、テーマ H(テストと CI)。今の CI は、backend が ruff、mypy、pytest、frontend が lint、型検査、Vitest、Prettier だけを流す。

- frontend の Vitest は `src/lib/` の表示の決まり(関数)だけを確かめ、画面は描かない。画面を開く確かめは、PR ごとに手で Playwright のスクリプトを書いて流してきた(ADR 0030 の「キーボード操作や読み上げの扱いを自分で確かめる」)。テーマ E(ADR 0056)では、フォーカスが帯に隠れないこと、輪、24px の的、11px の文字、完成の読み上げ、曜日ごとの一覧を、その場のスクリプトで測った。スクリプトはリポジトリに無いので、次の変更で崩れても気づけない
- ADR 0056 の再検討する条件に「自動の検査(axe など)を足すとき」とある
- CI は `next build` を流さないので、本番のビルドだけで落ちる誤り(サーバーとクライアントの境目、metadata、環境変数の確かめ)は、手でビルドするまで見えない
- 本番ビルドは、フォント(しっぽり明朝と Zen 角ゴシック New)を `next/font/google` でビルドのときに取りに行く。2026-10-23 と 24 に、手元の本番ビルドが Google Fonts の取得の打ち切りで 2 回落ち、流し直すと通った
- OG 画像とアイコンを撮る `frontend/brand/make.py` は backend の Python で動かす道具で、CI の lint の外にある

## 検討した選択肢

通しの試験の範囲

1. 画面だけ。CI で frontend を本番ビルドして立て、Playwright で開く。ブラウザが呼ぶ Route Handler(`/api/...`)は試験の中で差し替え、ログインは試験用の鍵で作ったセッションで入る。速く、結果が決まっていて、OpenAI も DB も要らない。backend との食い違いは、今ある OpenAPI の型の照合で守る
2. backend と DB も CI で立て、本物に近い通しで確かめる。LLM を偽物に差し替える仕組みと DB の種のデータが要り、CI が遅く重く、落ちやすい
3. 通しの試験は入れず、画面を開いて axe で検査するだけにする。操作の流れ(道標を作る、もう取った、消す)は確かめない

axe で CI を落とす基準

1. WCAG 2.2 の A と AA の規則に当たる違反は全て落とす。わざとそうしているものは、理由を付けて除外の一覧に書く
2. axe が critical と serious に分けた違反だけ落とす。軽い違反は溜まる
3. 結果を出すだけで落とさない

フォントの取得の打ち切り

1. Google のまま、CI のビルドを落ちたら流し直す。使う人の読み込みは今のまま(Next が文字の範囲ごとに分けた小さいファイルを配る)
2. フォントのファイルをリポジトリに入れて手元に置く。ビルドがネットに頼らないが、日本語のフォントは 1 太さ数 MB で、範囲ごとに分けないと各ページが重くなり、分けるとファイルが数百になる
3. 今のまま、落ちたら手で流し直す

make.py

1. Python のまま、CI の backend の job で ruff の対象に足す
2. frontend の Node の Playwright に移す。favicon.ico を作る部分の書き直しか、依存の追加が要る

## 決定

高橋さんが、範囲は 1、基準は 1、フォントは 1、make.py は 1 を選んだ。

- frontend に `@playwright/test` と `@axe-core/playwright` を足し、通しの試験を `frontend/e2e/` に置く(`pnpm test:e2e`)。Vitest は `e2e/` を対象から除く
- 試験は本番ビルド(`next build` のあと `next start`)に対して流す。手元でも CI でも、試験の立ち上げが試験の設定の環境変数でビルドしてから立てる(古いビルドや、残っているサーバーを検査せず、ビルドの `SITE_URL` も試験の origin と 1 か所で持つ)。ブラウザは Chromium だけ。試験用の `AUTH_SECRET` などは試験の設定に書き、本物の鍵は使わない
- ブラウザが呼ぶ `/api/` は、まず全て止め、その試験で使うものだけを決まった JSON で返す。差し替えていない `/api/` が呼ばれたときと、差し替えたのに呼ばれなかったときは、試験の終わりに落とす。返す道標は `src/lib/sample-plan.ts` の見本の道標から作る。ログインが要る画面は、試験用の鍵で `next-auth/jwt` の encode で作ったセッションの cookie で開く
- 1 つ目の PR では、全ての画面を幅 375px と 1280px、明るい見た目と暗い見た目で開き(畳んだ欄は開く)、フォントの読み込みを待ってから、axe で WCAG 2.2 の A と AA の規則(タグ wcag2a、wcag2aa、wcag21a、wcag21aa、wcag22aa)を検査して、違反が 1 つでもあれば落とす。除外は理由を付けて試験の中の一覧に書く。ページの地の方眼の線(body の background-image、透明度 5% の飾り)と、切符の切り欠きと路線の駅の点と線(::before と ::after の飾り)があると、axe は地の色を決められず、その上の文字の色の差を判定しない(incomplete)。どれも文字に重ならない飾りなので、axe を流す前にその飾りだけを消して確かめる。ほかの疑似要素は消さないので、新しい疑似要素で判定できない文字が出れば落ちる。それでも axe が判定できない文字は、手で色の差を測り、axe の理由ごとにその文字を試験の中の一覧に書いて許す。記号だけの文字(「→」6.61 以上、「◇」5.10 以上)、傾けた見本の切符の「柱」(4.91 以上)、道しるべの絵の文字(5.10 以上)、横に動かす帯の端で一部が隠れた終点の職業名(5.64 以上)、地の上に浮かせた見た目の切り替えのボタン(半透明の地の後ろが最も濃いか最も明るい色でも 4.57 以上)。一覧に無い文字と、axe が色の差を測れたのに足りない文字(1 文字の文字は、足りなくても違反でなく判定できないと出る)は落とす。同じ画面を幅 320px で開き、横にはみ出さないこと(1.4.10)も確かめる。画面は、トップ(ログイン前と後)、ログイン、利用規約、プライバシーポリシー、無いページ、一覧、結果(道のり、時間割帳、作成中、失敗)
- 2 つ目の PR で、操作の流れ(作成中を見たあとの完成の読み上げとタブの題、もう取ったの知らせ、消す、曜日ごとの一覧)を足す
- CI の frontend の job に、Playwright の Chromium の用意と `pnpm test:e2e` を足す。ログに Google Fonts への取得の失敗(`requesting https://fonts.googleapis.com/…` か `https://fonts.gstatic.com/…`)が出て落ちたときだけ 2 回まで流し直し、ほかの失敗はすぐ落とす。試験が落ちたら、記録(trace と画面写真)を CI に残す
- CI の backend の job に、`uv run ruff check --line-length 100 ../frontend/brand/make.py` を足す

## 理由

- 画面だけの通しの試験は、OpenAI と DB を使わずに速く決まった結果を出せる。今まで PR ごとに手で書いていた確かめ(はみ出し、輪、読み上げの枠)を残して、次の変更でも流せる
- 差し替え忘れを失敗にすれば、試験が backend に届いて結果が揺れることが無い
- axe の違反を全て落とせば、ADR 0056 で寄せた状態を、これから足す画面でも守れる。わざとそうしているものは除外の一覧に理由と一緒に残るので、レビューで見える
- フォントは、使う人の読み込みを変えずに、CI のビルドが一度の打ち切りで落ちないようにする。手元に置く案は、ページを重くするか、ファイルを数百に分けることになる
- make.py はたまにしか動かさないので作り直さず、lint だけ CI に入れて崩れを防ぐ

## 受け入れたトレードオフ

- 通しの試験は Route Handler と backend を通らない。食い違いは OpenAPI の型の照合と backend のテストで守る
- 本物の LLM の答えではなく、見本の道標を返す。推薦の質は実験(ADR 0048、0055)で測る
- CI の frontend の job が、ビルドと試験の分だけ長くなる
- フォントの取得が長く止まると、流し直しても CI は落ちる
- 流し直すかは、Next(Turbopack)が出す取得の失敗の文で見分ける。Next がその文を変えたら、フォントで落ちても流し直さずに落ちる
- axe は自動で分かる違反だけを見る。判定できない色の差と、読み上げソフトで聞く確かめは、これからも手で行う
- 手元の試験は毎回ビルドするので、1 分ほど長くかかる

## 再検討する条件

- CI の frontend の job が 10 分を超えるとき
- 流し直してもフォントの取得で落ちることが続くとき(手元に置く案)
- 試験で差し替えた API と backend の食い違いが本番で見つかったとき(backend と DB も立てる案)
- axe の除外の一覧が増えて、理由を保てなくなったとき
