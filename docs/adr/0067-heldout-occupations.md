# 0067. 確かめ用の 20 職業を別に取っておき、直しを決めたあとにだけ平均で測る

- ステータス: 承認
- 日付: 2026-10-26

## 文脈

- ADR 0063 の検索の変更は、評価データの初めの 30 職業の取りこぼしを見て決めた。50 職業で比べ直すと、再現率が上がったのは初めの 30 職業(+6.4 ポイント)で、変更を決めるときに見ていない足した 20 職業では上がらなかった(-1.2 ポイント、ADR 0064)
- ADR 0065 では、50 職業の取りこぼしを見て読み取りの指示文を直し、同じ 50 職業で測った。改善は出ず、指示文を同じ職業で直し続けると、その職業に合わせただけになりやすいので戻した
- 評価データの 50 職業は、取りこぼしや選んだ科目を職業ごとに見てきたので、直しの効き目を偏りなく確かめる職業がもう無い
- 判定は Claude のサブエージェントで行うので、職業を足しても OpenAI の費用はかからない。検索だけの測りもほぼ 0 円で、推薦を通す pair は 20 職業 × 3 回で約 110 円

## 検討した選択肢

1. 別のファイルで取っておく。確かめ用の職業と判定を `backend/eval/heldout/` に置き、今の 50 職業は開発用にする。直しの調べと試しは開発用だけで行い、確かめ用は直しを決めたあとに流して、平均と検定だけを見る
2. 足すたびに確かめ、使ったら開発用に移す。確かめ用はいつも使っていない職業になるが、直しのたびに職業を足して判定する手間がかかり、学科の授業で備えられる職業が尽きやすい

確かめ用の数は 20、30、10 を比べた。20 なら再現率の 10 ポイントほどの差を見分けられ、pair は約 110 円。30 は見分けられる差が少し小さくなるが(pair 約 170 円)、学科の授業で備えられる職業はもう 58 を使っていて(開発用 50、判定して外した 8)、似た職業や授業の少ない職業が増えやすい。10 は大きな悪化を見つける程度にしか使えない。

## 決定

高橋さんが 1 と 20 職業を選んだ。

- 確かめ用は `backend/eval/heldout/occupations.json` と `judgments.json` に置く。形は開発用と同じで、判定の CLI と実験の CLI の `--dataset` と `--judgments` でそのまま扱える。判定のファイルの頭(年度、学科、判定者、科目の前半と後半の並び)は開発用から写す
- 20 職業と予備 5 つは、学科の職種の割合(ADR 0064)に合わせて Claude が出し、高橋さんがそのまま選んだ。今の 50 職業、外した 8 職業(ADR 0054、0064)と重ならないようにし、学科の授業より細かい職種(XR エンジニア、バックエンドエンジニア、生成 AI のアプリケーションエンジニア)と授業の少ない職業(電機メーカーの商品企画、デジタルマーケター)も混ぜた

| 区分 | 職業 |
|---|---|
| SE・IT | HPC・並列計算エンジニア、コンパイラ・言語処理系のエンジニア、OS・ミドルウェア開発エンジニア、ネットワーク機器の開発エンジニア、XR(AR・VR)エンジニア、バックエンドエンジニア、生成 AI のアプリケーションエンジニア、エッジ AI エンジニア |
| 技術職 | パワーエレクトロニクス(電源回路)エンジニア、計測機器の開発エンジニア、自動運転・運転支援(ADAS)のエンジニア、宇宙・衛星の通信機器エンジニア、ドローンの制御エンジニア |
| 総合職・営業 | 半導体商社の FAE(技術サポート)、電機メーカーの商品企画、デジタルマーケター(データ活用) |
| 研究・開発 | 信号処理の研究者(大学院進学)、情報理論・暗号の研究者(大学院進学)、生体信号(脳波・心電)の計測エンジニア |
| 生産技術 | 電子機器の品質保証・信頼性エンジニア |

- 予備は、音声認識エンジニア、アナログ回路設計エンジニア、通信キャリアの基地局エンジニア、SRE(サイト信頼性エンジニア)、家電メーカーの組込みソフトウェアエンジニアの順に使う
- 手書きのスキルは Claude が下書きし、高橋さんがそのまま選んだ(判定者には見せない)。最初の下書きは科目名をそのまま使ったもの(コンパイラ、オペレーティングシステムなど)が多く、5 個ずつで、開発用(ほとんど 4 個、説明的な言い方)と形が違い、手書きのスキルの検索が甘く出るとレビューで分かったので、科目名を使わない説明的な 4 個に書き直し、高橋さんが選んだ。判定者はスキルを見ていないので、判定はそのまま使う
- 判定は ADR 0054 と同じ(指示文 `backend/eval/judge-prompt.md`、3 つの立場 × 前半と後半の 6 体の Claude、188 科目、職業名だけを渡す)。期待する科目が 1 つも無い職業は予備と入れ替え、中心が 1 票だけの科目は高橋さんが決める
- 判定の結果、XR(AR・VR)エンジニアは 6 体とも中心に挙げた科目が無く、期待する科目が 0 だったので、予備の音声認識エンジニアと入れ替えた。中心が 1 票だけの科目は 6 件(どれも残り 2 票は土台)で、高橋さんが開発用と同じく判定者の多数に合わせて全て土台に決めた。確かめ用の期待する科目は計 58、1 職業に 1〜5
- 確かめ用の使い方
  - 直しの調べ、試し、指示文や設定の選びは開発用の 50 職業だけで行う
  - 確かめ用は、開発用で直しを決めて ADR に書いたあとに流し、平均と検定だけを見る。検索だけなら `evaluate`、推薦を通すなら `experiment pair` か `run` に `--dataset` と `--judgments` を付けて流し、`experiment compare` で比べる
  - 確かめ用の職業ごとの結果(順位、取りこぼし、選んだ科目、結果の JSON の生の出力)は見ない。見てしまったら、その職業を開発用に移し(2 つの評価データと判定の間で職業と票を移し、両方の期待する科目を作り直し、試験の職業の数を直す)、確かめ用に予備か新しい職業を足す
  - 確かめ用で測った直しは、その結果で採るか採らないかを決め、変えてから同じ確かめ用で測り直さない
  - 確かめ用を使ったら、何を確かめ、どうなったかを README に書く
- 見ない決まりは道具で守る。確かめ用の評価データに `"heldout": true` の印を持たせ、印を見て次のようにする(最初は `evaluate --summary` と `--out` を付けて流す決まりにしたが、付け忘れると漏れ、失敗の文にも選んだ科目や読み取りが出るとレビューで分かり、高橋さんが道具で守る案を選んだ)
  - `evaluate` は平均の再現率だけを出し、止まったときも理由を出さず、警告のログを止める(開発用でも `--summary` で平均だけを出せる)
  - `experiment run` と `pair` は、結果を git の管理外の `backend/data/heldout-runs/` にだけ書き、`--out` を受け付けない(コミットされる場所に書かれると職業ごとの生の出力が残る)。進みの行の失敗の理由、止まった理由、思わぬ失敗のトレースバックを出さず、警告のログも止める
  - 隠す文と警告のログの止め方は、評価データの読み込みの隣に 1 か所で置き、`evaluate` と `experiment` が同じものを使う
  - `evaluate_selection` は職業ごとの結果しか出さないので、確かめ用を断る

## 理由

- 直しを決めた職業と確かめる職業を分ければ、ADR 0064 と 0065 のように、見た職業に合わせた分を効き目と取り違えない
- 判定は OpenAI の費用がかからず、判定と実験の道具はファイルの置き場を変えるだけで使える
- 印をデータの側に持たせれば、オプションの付け忘れでも職業ごとの結果が出ない

## 受け入れたトレードオフ

- 確かめ用の 20 職業では、再現率の 10 ポイントほどより小さい差は見分けられない。開発用の 50 職業と合わせて読む
- 道具が守るのは出力と書き先までで、`backend/data/heldout-runs/` の結果の JSON は開けば見られる。開かない決まりを CLAUDE.md に書いて守る
- 確かめ用で止まったときや推薦が失敗したときの理由は出ないので、原因は開発用で調べる
- 判定者が開発用と同じなので、判定の偏りは開発用と確かめ用で共通に入る
- 職業の候補を Claude が出すので、Claude の見方が入る(学科の職種の割合を根拠にし、高橋さんが選ぶことで薄める)
- 同じ学科の職業なので、開発用と近い職業がある(バックエンドエンジニアと Web エンジニア、音声認識エンジニアと画像・音声処理エンジニア、生体信号の計測エンジニアと医療機器の開発エンジニア、半導体商社の FAE と技術営業など)。開発用の近い職業を見て決めた直しは、確かめ用でも効きやすい。確かめ用が測るのは見ていない職業名への効き目で、新しい分野への効き目は測り切れない
- `experiment` の進みの行は、確かめ用でも職業名、費用、時間を出す(検索や選び直しの結果は出さない)

## 再検討する条件

- 確かめ用の職業を見てしまって開発用に移し、確かめ用が 15 職業を下回ったとき
- 確かめ用を 5 回使ったとき(使うたびに、確かめ用で良かった直しが残り、確かめ用に合った直しが少しずつ混ざる)
- 学科や年度を増やすとき
