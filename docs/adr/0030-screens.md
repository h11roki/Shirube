# 0030. 画面は Tailwind だけの部品で作り、Route Handler だけを呼び、型は生成物をコミットして CI で照合する

- ステータス: 承認
- 日付: 2026-10-19

## 文脈

フェーズ 8 で、職業と回生を入れる画面、道標の結果画面、自分の道標の一覧を作る。道標は API が待ちで受け付け、worker が作り、画面はポーリングで待つ(ADR 0029)。ログインと Route Handler の転送はできている(ADR 0028)。

画面に要るのに今の API に無いものが 2 つある。自分の道標の一覧と、学科で分かれたクラスの選び方である。クラスの選択は今、選べないクラスを送ったときの 422 の文でしか分からない。API の型は FastAPI の OpenAPI から openapi-typescript で作ると決めてある(ADR 0029)が、バックエンドとのそろえ方は決めていない。

## 検討した選択肢

画面の部品

1. Tailwind だけで自前に書く
2. shadcn/ui(Radix + Tailwind の部品をリポジトリに写す)
3. 部品のライブラリ(Mantine など)

API の型のそろえ方

1. バックエンドの OpenAPI と生成した型をコミットし、CI で作り直して差を見る
2. ビルドと型検査のたびに生成する(コミットしない)

学科で分かれたクラスの選び方

1. 選ぶ必要のある科目と選べるクラスを返す API を足し、入力画面で初めから選ばせる
2. POST の 422 に選べるクラスを欄で入れ、その場で選ばせて送り直す
3. 422 の文を見せ、利用者が科目とクラスを打ち込む

自分の道標の一覧

1. 新しい順に 50 件の要約を返す
2. 作った時刻を目印にしたページ送り

画面がデータを取る道

1. 画面はブラウザの部品(Client Component)にし、全て Route Handler を通す
2. 初めの表示は Server Component がサーバーで取り、送信とポーリングだけブラウザから Route Handler を呼ぶ

ポーリングの打ち切り

1. 待ちか作成中のまま 3 分で打ち切る
2. 止まった道標とみなす 15 分に合わせる
3. 打ち切らない

## 決定

高橋さんがどれも 1 を選んだ。

API(バックエンド)

- `GET /api/v1/plans`: 自分の道標を作った時刻の新しい順に 50 件まで、要約(id、状態、職業名、始める回生と学期、作った時刻)で返す。結果の JSON は読まない
- `GET /api/v1/class-choices?department=&grade=&term=`: 始める学期(term は省けば今日から)から 4 回生の秋学期までの残りの学期に、その学科向けのクラスが同じ学期に 2 種類以上開講される科目と、選べるクラスの記号を返す。記号の無いクラスは空の文字列。選ぶかどうかは利用者に任せ、選ばなければ今と同じくクラス未確定で置く(ADR 0025)
- どちらもログインが要り(ADR 0027)、年度は `CURRICULUM_YEAR`(ADR 0029)

型

- バックエンドの OpenAPI を `frontend/src/lib/api/openapi.json` に、openapi-typescript で生成した型を `frontend/src/lib/api/schema.ts` に置き、どちらもコミットする
- バックエンドのテストが、組み立てた API の OpenAPI とコミットした `openapi.json` が同じことを確かめる。書き出すコマンドはテストのフェイクで API を組み立てるので `backend/tests/` に置く
- フロントの CI が `schema.ts` を作り直し、差があれば落とす
- 生成したファイルは Prettier と ESLint の対象から外す

画面(フロント)

- 部品は Tailwind 4 だけで、画面に要る分を書く
- 入力(`/`)、結果(`/plans/[id]`)、一覧(`/plans`)の 3 つ。どれもログインが要り、ログインしていなければログインのボタンを出す
- 画面は Client Component にし、データは全て Route Handler(`/api/plans`、`/api/plans/[id]`、`/api/class-choices`)から取る。Route Handler はエンドポイントごとに置き、転送だけをする(ADR 0028)
- 学科は今は情(電子情報工学科)だけを選べる。他学科はフェーズ 10 で足す
- 入力画面は、回生と学期を選ぶとクラスを選ぶ科目を取りに行き、科目ごとに「まだ決めない」と選べるクラスを並べる
- 結果画面は、完了か失敗になるまで 2 秒ごとに GET を呼び、待ちか作成中のまま 3 分たったら打ち切って「時間がかかっています。あとで一覧から見てください」と、もう一度確かめるボタンを出す。完了なら、職業の解釈と前提とスキル、学期ごとの置いた科目(中心か土台か、理由、前提にする中心、クラス、コマ、単位)と週の時間割、置けなかった科目、中心につながらず外した土台を出す。失敗なら決まった文を出す
- 週の時間割は、学期ごとにコマ(曜日と時限)から並べる

PR の分け方

- 1 つ目: ADR、一覧とクラスの選択の API、OpenAPI と型の生成と照合
- 2 つ目: Route Handler の追加と 3 つの画面

## 理由

- 画面は 3 つで部品も少ない。Tailwind だけなら依存も生成されるファイルも増えない
- 生成物をコミットすれば、API を変えた PR に型の差分が出て読め、作り直し忘れは CI で分かる。フロントの CI とビルドに Python とバックエンドの依存が要らない
- 選ぶ必要のある科目を先に出せば、送ってから 422 で言い直されることがない。選ぶかどうかの判断は今の配置の決まり(選ばなければ未確定)のまま使える
- 一人が作る道標は多くないとみて、一覧は単純な 50 件にする。結果の JSON を読まないので軽い
- データの道を Route Handler の 1 つにそろえれば、テスト済みの転送をそのまま使え、エラーの扱いも 1 通りで済む。結果画面のポーリングも同じ書き方になる
- ふだんの生成は 10〜30 秒なので、3 分は十分に長い。worker が止まっていても利用者を待たせ続けない(ADR 0029 で残った穴)

## 受け入れたトレードオフ

- キーボード操作や読み上げの扱いを自分で確かめる
- API を変えるたびに、OpenAPI を書き出して型を作り直す
- API と Route Handler が 2 つずつ増える
- 51 件目からの道標は一覧に出ない
- 画面の初めの表示で一度「読み込み中」が出る
- OpenAI が遅いだけでも 3 分で打ち切ることがある(結果はあとで一覧から見られる)

## 再検討する条件

- 部品が増え、アクセシビリティの手当てが重くなったとき(shadcn/ui を入れる)
- 一人の道標が 50 件を超えることが多くなったとき(ページ送りにする)
- 初めの表示の速さが問題になったとき(Server Component で取る)
- 他学科を足すとき(学科の一覧を API から取る、フェーズ 10)
