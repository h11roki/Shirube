# 0004. ベクトル検索に pgvector を使う

- ステータス: 承認
- 日付: 2026-10-14

## 文脈

科目は学部・学科・学期・配当回生・曜日時限といった構造化属性を持ち、検索は常にこれらで絞り込んだ上で類似度順に並べる。データ量は1学科で数百科目、全学でも数万件。

## 検討した選択肢

1. pgvector(PostgreSQL 拡張)
2. ChromaDB
3. マネージドのベクトル DB(Pinecone 等)

## 決定

pgvector。科目メタデータと埋め込みを同じ PostgreSQL に置く。

## 理由

- 絞り込みと類似検索を SQL 1本で書け、トランザクションとバックアップも1か所で済む
- RDS / Aurora が標準で対応しており、デプロイ先を変えても使える
- ChromaDB はメタデータが二重管理になり、AWS 上で自前の永続化が要る
- マネージド DB はこの規模では過剰で、ベンダーと料金が増える

## 受け入れたトレードオフ

- 埋め込みの次元数が列型に固定される。モデル変更時はマイグレーションと再埋め込みが要る
- PostgreSQL のイメージを pgvector 入りにする
- HNSW インデックスは `vector` 型で 2000 次元までしか張れない

## 再検討する条件

- 件数が数百万を超え、検索レイテンシが要件を満たさなくなったとき
