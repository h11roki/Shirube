# 0015. 埋め込みは本文のハッシュで引く別の表に置き、索引は張らずに全件で比べる

- ステータス: 承認
- 日付: 2026-10-15

## 文脈

ADR 0005 でシラバスをセクション単位(授業の概要と方法 / 到達目標 / 授業スケジュール)のチャンクにし、ADR 0006 で text-embedding-3-small(1536 次元)で埋め込むと決めた。ADR 0014 でシラバスは年度単位で入れ替えるので、入れ替えのたびに syllabi の行は消えて作り直される。1学科でチャンクは約 1,600 件、全てを埋め込み直すと約 $0.01、数十秒かかる。検索は学科・入学年度・回生で絞った候補の授業コードの中から近いチャンクを探す(ADR 0014)。

## 検討した選択肢

埋め込みの保存

1. 埋め込みを「モデル × 本文のハッシュ」をキーにした別の表に置き、チャンクの表はハッシュで引く
2. チャンクの表にベクトルの列を持ち、入れ替えのたびに全て埋め込み直す

ベクトルの索引

1. 索引を張らず、全件の距離を計算する
2. HNSW 索引を張る

## 決定

埋め込みは別の表、索引は張らない。

| 表 | 主キー | 内容 |
|---|---|---|
| syllabus_chunks | (year, syllabus_code, section) | チャンクの本文と、その SHA-256。syllabi を ON DELETE CASCADE で指す |
| embeddings | (model, content_hash) | 埋め込みのベクトル(vector(1536))。どのチャンクからも引かれなくなった行は消す |

チャンクの本文は先頭に科目名、次にセクションの見出し、その後に本文を置く。授業スケジュールは各回のテーマとキーワードを並べ、回の番号と注記は入れない。本文が空のセクションはチャンクにしない。

埋め込みは `EmbedSyllabi` ユースケースが行う。その年度のシラバスを DB から読んでチャンクを作り、まだ埋め込みの無いハッシュだけを API に送り、埋め込みを保存してからチャンクを入れ替える。取り込みの順は `ingest syllabi` の後に `embed`。

モデル名と次元数は設定値で持つ。次元数を変えるときは列の型を変えるマイグレーションと全件の再埋め込みが要る。

## 理由

- シラバスを入れ替えても本文が同じチャンクは API を呼ばずに済み、再取り込みが速く、途中で失敗しても保存済みの埋め込みは次に使える
- モデルをキーに含めるので、モデルを変えても古い埋め込みと混ざらない
- 1学科 1,600 件なら全件の距離計算でも数ミリ秒で、結果は厳密。候補の授業コードで絞っても取りこぼさない。HNSW のような近似索引は、絞り込みと組み合わせると候補を取りこぼすことがある

## 受け入れたトレードオフ

- 表が 2 つ増え、検索はチャンクと埋め込みを結合する
- 使われなくなった埋め込みを消す手順が要る
- `ingest syllabi` の後に `embed` を実行しないと、その年度のチャンクは空で検索に何も出ない

## 再検討する条件

- 全学に広げてチャンクが数万件を超え、検索が遅くなったとき(HNSW を足し、pgvector の反復スキャンで取りこぼしを抑える)
- 次元数の違うモデルに替えるとき
