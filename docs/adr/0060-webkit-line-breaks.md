# 0060. 折り返しの試験は WebKit でも流す

- ステータス: 承認
- 日付: 2026-10-24

## 文脈

- 通しの試験(ADR 0057)は Chromium だけで流している。iPhone のブラウザは全て WebKit で描く
- 決まった文の見出しの初めの案(ADR 0059 の初めの版、`word-break: auto-phrase`)は Chromium だけで効き、iPhone では見出しが語の途中で折れたままだった。Chromium だけの試験では見つからず、レビューで分かった
- 今の折り返しの試験(ADR 0058、0059)を WebKit で流すと、決まった文の見出しは全て通り、行先表示の板の 4 件が Chromium と違う語の切れ目で折れた。結果の画面の「半導体・LSI / 設計エンジニア行」が WebKit では「半導体・LSI 設計 / エンジニア行」、作成中の画面の「システム / 保守技術者行」が「システム保守 / 技術者行」。どちらも語の途中では折れていないが、板の試験は Chromium の行を決め打ちしている
- この 3 つの名前の語の分け方(`Intl.Segmenter`)は、手元の Chromium と WebKit で同じだった。違いは行の組み方(`text-wrap: balance`)から来た。ただ、結果と作成中の画面の板はブラウザで語に分けるので、語の分け方もブラウザの辞書や版で違いうる
- 見出しの読み上げの名前の試験(ADR 0059)は Chrome の DevTools Protocol で読むので、WebKit では流せない
- 次に、中身が変わる文(切符の授業名と行き先)も語の切れ目で折る(高橋さんが選んだ)。語の切れ目はブラウザの辞書で決まるので、WebKit の辞書でも確かめたい

## 検討した選択肢

1. 折り返しの試験(`e2e/line-breaks.spec.ts`)を WebKit でも CI で流す
2. 流さない。WebKit は手で確かめる

## 決定

高橋さんが 1 を選んだ。

- Playwright の設定に chromium と webkit の 2 つの project を置き、webkit は `line-breaks.spec.ts` だけを流す。webkit は iPhone 13 のまね(`devices["iPhone 13"]`。画面の幅は試験ごとに決める)
- 板の試験は行を決め打ちせず、手で書いた語の並び(「組込み」「ソフトウェア」「エンジニア行」など)で、どの行も語をそのまま並べたものかと、板が置いた欄(作成中の画面では道しるべの絵の横)からはみ出さないかを確かめる。語の並びは折れてよい所(人が見て語の途中でない所)を書いたもので、ブラウザで折る所が違っても、そこで折れていれば通す。辞書がそれより細かく分けてそこで折れたら落ちる。見本の板が 1 行に収まる試験は行を決め打ちしたまま
- 読み上げの名前の試験には `@cdp` の印を付け、webkit の project で外す(どの試験をどのブラウザで流すかを設定の 1 か所で決める)
- CI の frontend の job で、Chromium と WebKit を用意する

## 理由

- iPhone で語の途中で折れることは、Chromium だけでは見つからない。試しに見出しを auto-phrase に戻すと、Chromium の試験は全て通り、WebKit の 4 件が「道標を作っ / ています」「プライバシーポリシ / ー」などを出して落ちた
- 画面の一覧と axe、操作の流れの試験はブラウザでほとんど変わらないので、WebKit で流すのは折り返しの試験だけにして、CI がのびるのを抑える
- 語の切れ目で折れているかを確かめれば十分で、どの語の切れ目で折るかはブラウザの行の組み方(`text-wrap: balance` など)で変わってよい

## 受け入れたトレードオフ

- CI の frontend の job がのびる。入れたときの CI で、3 分 18 秒から 4 分 37 秒になった(WebKit の用意で 34 秒、折り返しの試験 26 件で 52 秒)。Google Fonts の取得で落ちて流し直すときは、WebKit の分も流し直す
- webkit は iPhone 13 のまね(触れる画面、マウスを乗せられない、画素の密度 3)で流すので、WebKit の描き方のほかに、iPhone の画面での違い(切符を傾けないなど)も試験に入る。iPhone で見える形を確かめるのがねらいなので受け入れる
- CI の WebKit は Linux 版で、iPhone の WebKit とは字の描き方が少し違う(フォントはどちらも同じウェブフォント)。iPhone で折れる所と少しずれうる
- 板の試験は折れる所を決め打ちしなくなるので、狭い画面で字を縮めることは、見本の板が 1 行に収まる試験でだけ確かめる

## 再検討する条件

- 折り返し以外にも、WebKit でだけ崩れる画面が見つかったとき(ほかの試験も WebKit で流すか)
- CI の時間が気になるとき
