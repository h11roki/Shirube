# 0001. フロントとバックエンドを1つのリポジトリで管理する

- ステータス: 承認
- 日付: 2026-10-14

## 文脈

フロント(Next.js / TypeScript)とバックエンド(FastAPI / Python)の2言語構成で、開発者は1人。初期は API の形が頻繁に変わる。

## 検討した選択肢

1. モノレポ: `frontend/` と `backend/` を同一リポジトリに置く
2. 分割: 言語ごとにリポジトリを分ける

## 決定

モノレポにする。

## 理由

- docker compose と CI の設定が1本で済む
- バックエンドの OpenAPI からフロントの型を生成でき、API 契約のズレを同じコミット内で検出できる
- 横断的な変更(API の項目追加と画面の対応)が1つの差分で追える

## 受け入れたトレードオフ

- CI が両方のツールチェーンを扱う。差分のない側のジョブも走る
- 2言語の設定ファイルが同居する

## 再検討する条件

- フロントとバックエンドのデプロイ周期を分けたくなったとき
- 開発者が増え、リポジトリ単位で権限を分ける必要が出たとき
