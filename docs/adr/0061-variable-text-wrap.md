# 0061. 中身が変わる文(授業名と行き先)も、語の切れ目でだけ折る

- ステータス: 承認
- 日付: 2026-10-24

## 文脈

- 決まった文の見出しは手で句に分けた(ADR 0059)。授業名と行き先(職業名)は中身が変わるので、手で分けられない
- 道のりの切符の授業名の欄は、幅 320px で 94px(6 字ほど)、375px で 149px、広い画面(1024px と 1280px)でも 155px しかない。右の半券(76px)と柱の判の余白(40px)を引くため。見本の道標の授業名は、320px で 6 つとも語の途中で折れ(「データエン / ジニアリン / グ基礎」「データ構造 / とアルゴリ / ズム」)、1280px でも「データエンジニアリ / ング基礎」「データ構造とアルゴ / リズム」と折れる。時間割帳の切符は、320px で「データエンジニア / リング基礎」、375px で「データエンジニアリング基 / 礎」
- 道のりの終わりの見出しは幅 320px で「データサイエンティス / トへ」、帯の終点(11px)は 320px と 375px で「データサイエンテ / ィスト」と折れる
- トップの見本の切符の授業名は `PHRASE_WRAP`(`word-break: auto-phrase`)で折っていて、Chromium だけが対応する
- 行先表示の板(ADR 0058)は、`Intl.Segmenter` で語に分け、字を縮めて語の切れ目でだけ折る
- 学科の時間割表の授業名 267 件を板の決まりで語に分けると、9 字より長い語を含む名前が 39 件あった。開き括弧の前で折れないこと(「ゼミナール【建設人としての日本語」が 1 語になる)と、1 字の語(「の」「と」)を前後の語につなぐこと(「社会のフィールドワーク」「アルゴリズムとデータ」)が主な理由

## 検討した選択肢

4 つと 3 つの案を、幅 320px と 375px の写真で比べた。

切符の授業名

1. 今のまま
2. 語の切れ目でだけ折る(切符の形は今のまま)。欄が 6 字ほどなので、長い語は語の中で折れ、閉じ括弧だけが行の頭に来ることもある
3. 狭い画面では半券を切符の下に回す(折り方は今のまま)。欄は 10 字ほどに広がるが、「データエンジニアリン / グ基礎」と語の途中で折れる名前が残る
4. 3 と 2 を合わせる

行き先(道のりの終わりと帯の終点)

1. 今のまま
2. 板と同じに、幅に合わせて字を縮め、語の切れ目でだけ折る
3. 語の切れ目でだけ折る(字は今のまま)。320px で「データ / サイエンティストへ」と 2 行になる

語の分け方に足す決まり(1 字のひらがな)

1. 1 字のひらがなは前の語に付け、そのあとで折る
2. 板の決まりのまま、1 字の語は前後の語とつなぐ

## 決定

高橋さんが、切符の授業名は 4、行き先は 2、1 字のひらがなは 1 を選んだ。

語の分け方(`src/lib/words.ts`、板と授業名と行き先で共有する)

- 開き括弧と開き引用符の前にも折る所を作る(前に語か記号があるとき)。ADR 0058 は記号の前には折る所を作らないとしていたが、開き括弧は行の頭に来てよく、授業名には括弧の続く名前が多い(「特殊講義（専門）Ⅲ（深層学習の応用）」「専門ゼミナール【…】」)。高橋さんに案を見せたときに含めていた
- 1 字の助詞(の、と、や、を、に、へ、で、が、は、も)は前の語に付け、そのあとで折る。一覧に無い 1 字のひらがな(頭に付く「お」「ご」など)と、漢字や英字の 1 字(「者」「光」「副」)は ADR 0058 のまま前後の語とつなぐ。初めは 1 字のひらがなを全て助詞として扱ったが、レビューで「お」「ご」のあとでも折れると分かり、一覧に限った
- 学科の授業名 267 件では、9 字より長い語を含む名前が 39 件から、開き括弧で 20 件、助詞で 9 件になった(助詞を一覧に限っても同じ)。残りは辞書が 1 語とする長いカタカナ語(「コンピュータアーキテクチャⅠ」14 字、「オペレーティングシステム」12 字)

切符の授業名

- 全ての幅で、授業名を語に分け、`Phrases`(ADR 0059)で語のあいだに読み上げから外した `<wbr>` を挟んで並べる。行より長い語だけ `overflow-wrap: anywhere` で語の中で折る
- 幅 640px 未満(切符が 1 列に並ぶ幅)では、半券(コマ、クラス、単位)を切符の下に横に並べ、切り取り線と切り欠きも下に回す。柱の判は右上に置く。時間割帳の切符も同じ
- トップの見本の切符は、幅が決まっていて 2 つの名前とも 1 行に収まるので、語の分け方だけを使い、`PHRASE_WRAP` をやめる(サーバーの辞書で分ける)

行き先

- 道のりの終わりの見出しは、板と同じに字を `clamp(1.125rem, 5.9vw, 1.5rem)`(幅 640px 以上は今の 24px)にし、語のあいだと「続きます」の前に読み上げから外した `<wbr>` を挟む。名前の最後の見た目の 1 字と「へ」を折らない組にする
- 帯の終点は語のあいだに `<wbr>` を挟み(字は 11px のまま)、幅を 8em から 9em に広げる。語の切れ目でだけ折ると、「組込みソフトウェアエンジニア」は 8em では「組込み / ソフトウェア / エンジニア」の 3 行になり、2 行で切れて「エンジニア」が見えなくなる
- トップの見本の道のりは、サーバー(Node)で語に分けた結果を道のりの部品(Client Component)に渡し、ブラウザで分け直さない。トップの道のりはサーバーで描いてからブラウザで描き直すので、2 つの辞書の分け方が違うと描き直しが食い違う(`Intl.Segmenter` の無いブラウザでは React の hydration の誤りになる)。結果の画面の道のりはブラウザでだけ描くので、ブラウザで分ける

試験

- 語の分け方の決まりは Vitest で偽の Segmenter を使って確かめる
- 通しの試験(Chromium と WebKit、ADR 0060)で、幅 320px と 375px で、道のりの終わり(結果の画面と、トップの見本の「続きます」)、帯の終点、切符の授業名が、手で書いた語の並びでだけ折れ、包む要素からはみ出さないかを確かめる。結果の画面の道のりの終わりは幅 320px で 1 行に収まるか、帯の終点(見本と長い名前 3 つ)が 2 行に収まるか、`Intl.Segmenter` の無いブラウザでもトップの描き直しで React の誤りが出ないか、狭い画面で半券が授業名の下にあり、広い画面で右にあるかも確かめる
- 行き先と語の分け方を 1 つ目の PR、切符を 2 つ目の PR で入れる

## 理由

- 授業名の欄は狭い画面だけでなく広い画面でも 9 字ほどで、全ての幅で語の途中で折れていた。語の切れ目で折れば語のまとまりが崩れない。狭い画面で半券を下に回すと欄が 13 字ほどに広がり、語の切れ目で折っても行が増えすぎない
- 行き先は板と同じ職業名なので、同じ決まりにそろえる
- 括弧とひらがなの決まりは、学科の授業名で効き目を数えてから足した

## 受け入れたトレードオフ

- 狭い画面では切符の形が変わる(半券が下に横並び)。共有カード(OG 画像)とトップの見本の切符は横の半券のまま
- 狭い画面では道のりの終わりの字が少し小さくなる(幅 320px で 24px から 19px ほど)
- 辞書が 1 語とする長いカタカナ語は、欄より長いと語の中で折れる。閉じ括弧だけが行の頭に来ることもある
- 助詞は一覧に限るので、一覧に無い 1 字の助詞(「か」など)のあとでは折れない
- 語の分け方はブラウザの辞書で決まる(ADR 0058、0060)。トップの見本の板と道のりと切符はサーバー(Node)の辞書で分ける
- 帯の終点が 1em 広がり、帯が少し長くなる

## 再検討する条件

- 語の切れ目がおかしい授業名が見つかったとき
- 切符の形を変えるとき(共有カードの切符と合わせるか)
- 助詞の一覧に無いもので、折れずに読みにくい名前が見つかったとき
