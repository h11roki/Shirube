# 0059. 決まった文の見出しは、手で句に分けて並べる

- ステータス: 承認(WebKit の折れ方を CI で確かめることは 0060)
- 日付: 2026-10-24

## 文脈

- 行先表示の板の折り返し(ADR 0058)を写真で確かめたとき、作成中の画面の見出し「道標を作っています」が、幅 320px で「道標を作っ / ています」と語の途中で折れていた。見出しは道しるべの絵と並ぶので幅が狭い
- 幅 320px と 375px の全ての画面の見出しを調べると、プライバシーポリシーの見出しも 320px で「プライバシーポリシ / ー」と折れ、行の頭に「ー」が来ていた
- トップの見出し(ADR 0046 のキャッチフレーズ)は、文を手で句に分け(`CATCHPHRASE`)、句ごとに inline-block の span で並べているので、どのブラウザでも句の切れ目で折れる。句の中には `PHRASE_WRAP`(`word-break: auto-phrase`)も付けているが、`auto-phrase` は Chromium だけが対応する
- この ADR の初めの版(同じ PR)は、トップの見出しが `PHRASE_WRAP` で句に折れていると読み違え、作成中の見出しに `PHRASE_WRAP` を付ける案を選んだ。レビューで、iPhone(どのブラウザも WebKit)では今のまま折れることが分かり、選び直した
- 句の並べ方で、見出しの読み上げの名前が変わる。Chrome の読み上げの木(DevTools Protocol の `Accessibility.getFullAXTree`)では、inline-block の句のあいだにも `<wbr>` にも空白が入り、「プライバシー ポリシー」になる(Chrome は `<wbr>` を改行として木に入れる)。トップの見出しは前から「履修に迷ったら、 なりたい職業から。」だった
- 切符の授業名と道のりの終わり(行き先)の見出しも語の途中で折れるが、中身が変わる見出しで、切符の欄の狭さも絡むので、別に決める

## 検討した選択肢

1. 決まった文の見出しは、トップの見出しと同じく手で句に分け、句の切れ目でだけ折る
2. `PHRASE_WRAP` を付けるだけ。Chromium だけが句で折る。「プライバシーポリシー」はカタカナの続く語で、auto-phrase では分けない
3. 中身が変わる見出しも含め、見出し全般に板と同じ語の切れ目の決まり(`Intl.Segmenter` と `<wbr>`)を使う
4. 見出しに `line-break: strict` を付ける。行の頭の「ー」は防げるが、幅 320px で「プライバシーポリ / シー」「道標を作っ / ています」と語の途中で折れるのは変わらない

## 決定

高橋さんが 1 を選んだ。

- 句を並べる部品(`Phrases`)を作り、トップ、作成中、プライバシーポリシーの見出しで使う
- 句のあいだに `<wbr>` を挟み、`word-break: keep-all` で句の中では折らない。1 つの句が行より長いときだけ、`overflow-wrap: anywhere` で句の中で折る(行先表示の板と同じ作り、ADR 0058)。`<wbr>` は aria-hidden で読み上げの木から外す
- 作成中の見出しは「道標を」「作っています」、プライバシーポリシーは「プライバシー」「ポリシー」に分ける。利用規約は 1 つの句
- 通しの試験で、3 つの見出しが幅 320px と 375px で、どの行も句をそのまま並べたものであること(句の途中で折れないこと)、文字を 200% にしても見出しが画面からはみ出さないこと、Chrome の読み上げの木の見出しの名前で句のあいだに空白が入らないことを確かめる。Playwright の名前の計算は `<wbr>` に空白を入れないので、Chrome の木を読む

### 句の並べ方

並べ方は、レビューの指摘(読み上げの名前に空白が入る、見出しの文が 2 度入る)で選び直した。5 つの並べ方を 3 つの見出しで比べた。どれも Chromium、WebKit、Firefox(Playwright のブラウザ)で句の切れ目でだけ折れた。

| 並べ方 | Chrome の読み上げの名前 | 文字を 200% にした幅 320px のトップの見出し | ほかの違い |
| --- | --- | --- | --- |
| 句のあいだに aria-hidden の `<wbr>`、`keep-all` と `overflow-wrap: anywhere`(選んだもの) | 「プライバシーポリシー」 | 画面に収まる(行より長い句は句の中で折れる) | |
| 句のあいだに `<wbr>`(行先表示の板と同じ) | 「プライバシー ポリシー」 | 画面に収まる | |
| 句ごとの inline-block の span(トップの見出しの前の作り) | 「プライバシー ポリシー」 | 画面に収まる | |
| 句ごとの span に `white-space: nowrap` | 「プライバシーポリシー」 | 右端が 572px で、ページが横に広がる(文字 125% でも 38px) | 行より長い句を折れない |
| 読み上げ専用の文(sr-only)1 つと、読み上げから外した(aria-hidden)見せる句 | 「プライバシーポリシー」 | 画面に収まる | 見出しの文が DOM に 2 度入り、写しや検索エンジンに 2 度出る。見えている見出しを VoiceOver で指でなぞっても読まれない |

## 理由

- `<wbr>` と keep-all は、どのエンジンでも句の切れ目でだけ折れる。文字を大きくして句が行より長くなっても、句の中で折れて画面に収まる
- `<wbr>` を読み上げの木から外すと、読み上げの名前に空白が入らない。見出しの文は DOM に 1 度だけで、見えている文がそのまま読み上げに出る
- 板と同じ作りなので、折る所を決める作りが 1 つで済む
- 決まった文なので、句は書く人が決められる

## 受け入れたトレードオフ

- 見出しの文を変えるときは、句の分け方も書き直す
- 1 つの句が行より長いと、句の中で字の切れ目で折れる
- 作成中の見出しは、読み上げ専用の「〇〇への」と見えている文のあいだに、Chrome の読み上げの名前で空白が入る(「データサイエンティストへの 道標を作っています」。この ADR の前から)。消すには文を DOM に 2 度書くことになるので、そのままにする
- 読み上げの名前は Chrome の木でだけ確かめる(DevTools Protocol に頼るので、試験も Chromium でだけ流せる)。WebKit と Firefox の折れ方は手で確かめた
- 中身が変わる見出し(授業名、行き先)はこの決まりの外

## 再検討する条件

- 中身が変わる見出しの折り返しを決めるとき
- 新しい決まった文の見出しが語の途中で折れたとき
- ブラウザが `<wbr>` の読み上げの扱いを変えたとき
