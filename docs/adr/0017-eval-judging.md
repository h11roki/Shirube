# 0017. 評価データの期待する科目は、立場の違う 3 体の判定の多数決で決め、割れたものは高橋さんが決める

- ステータス: 承認
- 日付: 2026-10-15

## 文脈

ADR 0016 では、評価データの期待する科目を Claude が下書きし、高橋さんが直すとした。最初の下書きは科目名から当てて選んだもので、シラバスを読み直すと理由が中身とずれた科目があった。また、名前から中身の分からない科目(特殊講義、実験、専門ゼミナールなど)は候補にすら上がらない。

一方、フェーズ 5 ではアプリの LLM がシラバスを読んで科目を選ぶ方向で考えている。評価の正解を同じ判断の癖を持つ LLM 1 体に作らせると、検索や選び直しを甘く採点しやすい。

## 検討した選択肢

1. 学科の科目を全て候補にし、立場の違う 3 体の LLM が独立にシラバスを読んで判定し、多数決で決める。割れたものだけ高橋さんが決める
2. Claude が 1 体でシラバスを読んで判定し、高橋さんが全てを確かめる
3. 高橋さんが全てを判定する

## 決定

選択肢 1。

- 候補は、その学科の 1〜4 回生に今年度開講されている専門・基礎専の科目全て(2026 年度の情は 82 科目)。科目名で絞らない
- 判定者は 3 体の LLM で、立場を分ける: 採用・育成担当のエンジニア(入社後すぐ使うか)、カリキュラムを設計する教員(必ず履修を勧めるか)、進路を考える 3 回生(就職した先輩が役立ったと言いそうか)
- 判定者に渡すのは、科目ごとのシラバスの抜粋(授業の概要と方法、到達目標、授業スケジュールのテーマ)と、職業名と必要なスキルだけ。既存の下書きや他の判定者の結果は見せない
- 判定者は職業ごとに各科目を「中心(授業の中心テーマがその職業のスキルを直接扱う)」「土台(基礎、または一部の回で触れる)」「関係なし」に分け、中心と土台にはシラバスの記述を根拠として 1 文付ける。迷ったら土台
- 2 体以上が中心とした科目を期待する科目にする。1 体だけが中心とした科目は高橋さんが決める
- 期待する科目の理由には、判定者の根拠(シラバスの記述)を使う

## 理由

- 全科目を読むので、名前から中身の分からない科目も漏れない(2026 年度の判定では、半導体・LSI 設計エンジニアに「電子情報工学実験Ⅱ」(SPICE と FPGA の実験)が加わった)
- 立場を分けた独立の判定と多数決で、1 体の判断の偏りを薄める。人が見るのは割れた箇所だけになり、手間が小さい
- 判定の根拠がシラバスの記述なので、正解を後から確かめられる

## 受け入れたトレードオフ

- 3 体は同じ系統の LLM なので、立場を分けても意見がそろいやすく、偏りを共有しうる(2026 年度は、中心の票が 1 体以上から入った科目と職業の組 47 のうち、46 で 2 体以上がそろい、割れたのは 1 組だけだった)
- 期待する科目が少ない職業がある(無線・高周波回路エンジニアは 2 科目)。その職業の再現率は 0、0.5、1 のような粗い数字になる
- アプリが OpenAI のモデルで選ぶ場合、判定者(Claude)とは系統が違うので答え合わせの循環は避けられるが、判定者の癖そのものは正解に残る

## 再検討する条件

- 評価の数字と高橋さんの実感が食い違うとき(高橋さんが全てを確かめる選択肢 3 に寄せる)
- 学科や年度を増やすとき(同じ手順で判定し直す)
