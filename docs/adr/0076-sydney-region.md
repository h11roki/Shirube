# 0076. 本番は AWS の新しい登録の無料プランのまま、シドニーで動かす

- ステータス: 承認
- 日付: 2026-10-31

## 文脈

- ADR 0075 で、新しい AWS アカウントのクレジットで EC2 を動かすと決めた。アカウントを作ったところ、2026 年 9 月からの新しい登録(Sign up for AWS (new))になり、無料プランのプロジェクトの地域は、AWS が住所の国から決めていた。候補はオハイオ、ストックホルム、シドニーの 3 つで、日本はシドニーに入り、後から変えられない
- 東京を使うには、アカウントを有料プランに上げて高度な機能を有効にするか、従来の登録(Sign up for AWS (advanced))で別のアカウントを作るしかない。無料枠の規約では、クレジットを受け取れるのは 1 つのアカウントだけ
- 新しい登録にはルートユーザーが無く、MFA は AWS Settings で付ける。無料プランは、クレジットを超えて請求されず、6 か月かクレジットを使い切ると閉じる
- 本番の DB には、利用者の番号(Google の sub)、道標、もう取ったと答えた授業、Caddy のログの IP アドレスが残る。今のプライバシーポリシーは、サーバーがどの国にあるかを書いていない

## 検討した選択肢

- 今の無料プランのまま、シドニーで動かす
- 今のアカウントを有料プランに上げ、高度な機能を有効にして東京で動かす(クレジットで 5 か月ほどは 0 円。そのあとは月 3,000 円前後がカードに請求される。元に戻せず、使用額の上限も付けられない)
- 従来の登録で別のアカウントを作り、東京で動かす(クレジットが付かず、初月から月 3,000 円前後)

## 決定

高橋さんが、今の無料プランのまま、シドニーで動かすことを選んだ。

- EC2 と Elastic IP は、プロジェクトの地域のシドニー(`ap-southeast-2`)に作る。サーバーの構成と手順は ADR 0075 のまま
- プライバシーポリシーに、データをオーストラリア(シドニー)の AWS のサーバーに保存することと、オーストラリアの個人情報の保護の制度(Privacy Act 1988 とオーストラリアのプライバシー原則)を書き足す。個人情報保護法の安全管理措置で、外国で個人データを扱うときはその国の制度を把握し、本人が知りうる状態に置くことになっているため
- ADR 0075 の AWS の予算の通知は付けない。無料プランではクレジットを超えて請求されないため。MFA は AWS Settings で付ける

## 理由

- 無料プランなら、最長 6 か月のあいだ費用が 0 円で、請求が起きる余地も無い。費用を抑えたいという高橋さんの方針に合う
- 日本からの往復は東京より 0.1 秒ほど延びるが、道標を作るのに 20 秒ほどかかるアプリで、OpenAI への往復も海外なので、使い心地への響きは小さい
- 有料プランに上げる案は 5 か月ほどは同じく 0 円だが、元に戻せず、使用額の上限を付けられないまま請求が始まりうる

## 受け入れたトレードオフ

- ページを開くたびの往復が東京より遅い
- 利用者のデータがオーストラリアに置かれる。ポリシーで知らせる
- 無料プランは 6 か月で閉じる。続けるなら、その前に有料プランに上げる。東京に移すなら、高度な機能を有効にしてから、東京にサーバーを作り直し、バックアップから DB を戻し、DuckDNS の向き先を替える

## 再検討する条件

- 無料プランが閉じる前(有料プランに上げて続けるか、止めるか、ほかに移るか)
- 遅さが使い心地の問題になったとき
