# 0035. 覚えたもう取った授業は推薦の候補から除き、入力の画面に畳んだ一覧で取り消せるようにする

- ステータス: 承認
- 日付: 2026-10-19

## 文脈

ADR 0034 で、前の学期に開講された授業は結果の画面で取ったかを聞き、取った授業は利用者ごとに科目名で覚えて、その道標から外すことにした。作業は 2 つの PR に分け、1 つ目(PR 31)で聞く、覚える、置き直す、戻すまでを作った。2 つ目では、覚えた授業を次に作る道標で使い、聞き直す手間を初回だけにする。

1 つ目の PR では、覚えは書くだけで読まれていない。2 つ目で決めることは 2 つある。

- 覚えた授業を、次の道標でどう扱うか
- 覚えた授業を、どこで見直して取り消すか(ほかの画面から逆の答えをほぼ同時にすると、覚えだけ道標と食い違うことがある。ADR 0034)

## 検討した選択肢

覚えた授業の扱い

1. 推薦の候補から除く: 検索の候補から先に除き、LLM は残りから選ぶ
2. 推薦はそのままにし、置くときに外す: LLM は取った授業も選びうるが、置くときに外して「もう取った授業」に出す

一覧と取り消しの場所

1. 入力の画面に畳んで置く
2. 別のページにする

## 決定

高橋さんが選んだ。扱いは 1、場所は 1。

- 道標を作るとき(worker の BuildPlans)、道標の持ち主が覚えた授業を、検索の候補から科目名で除く。合併科目は、利用者の学科のクラスのどれかの科目名を取っていれば、ページごと除く(同じ授業を別の名前で勧めない)。作るときに候補が無くなれば、その理由の文で道標を失敗にする
- 除くのは作るときだけ。作ったあとに覚えを変えても、作った道標は変えない(ADR 0034 のとおり、ほかの道標は開いて答えるまで置き直さない)
- 道標を受け付けるとき(RequestPlan)の「候補があるか」の確かめも、覚えた授業を除いて行う。除いて候補が無ければ 422 で「もう取ったと答えた授業は除いています」と返す
- 入力の画面に「もう取ったと答えた授業(n 科目)」を畳んで置き、開くと科目名の一覧と「取り消す」を出す。取り消すと覚えから除き、次に作る道標から候補に戻る。覚えが無ければ出さない。覚えた授業は、入力の画面のクラスの選択にも、候補と同じ決まり(合併はページごと、domain の left_out_codes)で出さない
- API は `GET /api/v1/taken-courses`(自分の覚えを科目名の順で)と `DELETE /api/v1/taken-courses/{科目名}`(覚えから除いて、残りを返す)。どちらも自分の覚えだけを読み書きする

## 理由

- 候補から除くと、検索の上位 30 件と推薦の枠を、もう取った授業が取らない。空いた枠にほかの授業が入る。高橋さんの「次に道標を作るときは推薦の入力に含めれば、2 回目以降は最初から正しい道標が出る」に当たる
- 置くときに外す形では、取った授業が推薦の枠を取り、その分ほかの授業が推薦されない
- 入力の画面に置くと、道標を作る前に、何が除かれるかをその場で見直せる。別のページは、作る前に気づきにくく、ページと導線が増える
- 受け付けるときも覚えを除いて確かめると、作れない道標を受け付けて worker で失敗させず、その場で理由を返せる(PR のレビューで、受け付けを今のままにすると原因の分からない失敗になると分かって変えた)

## 受け入れたトレードオフ

- 除いた授業は、その道標のどこにも出ない。何を除いたかは入力の画面の一覧で見る
- 科目名で除くので、名前の同じ別の授業も除かれる(ADR 0034 と同じ)
- 受け付けたあと作る前に覚えが増えて候補が空になると、道標は作れずに失敗する(受け付けの確かめとの間だけ)
- 覚えを取り消しても、作った道標には戻らない。その道標の「もう取った授業」から戻すか、作り直す
- 結果の画面で答えたときは、ADR 0034 のとおり聞いた授業だけを科目名で外すので、同じ道標に合併の別名が推薦されていれば残る(同じ学生に別名が 2 つとも開講されることはまれ)

## 再検討する条件

- 何を除いたかを結果の画面でも見たいという声が出たとき(道標に除いた授業を残す)
- 取った授業を、その授業の上に積む授業(柱)の推薦に使いたくなったとき
