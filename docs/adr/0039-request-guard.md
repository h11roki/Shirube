# 0039. 画面の転送は、ほかのサイトからの状態を変える要求を断り、本文を 64KB までに限る

- ステータス: 承認
- 日付: 2026-10-21

## 文脈

画面は、Next.js の Route Handler(`src/app/api/`)を経由してバックエンドを呼ぶ(ADR 0028)。Route Handler はログインを確かめ、Google の sub を入れた JWT を付けて、要求の本文をそのまま転送する。本番は誰でも Google でログインして使える公開にする(ADR 0038)。本番の前の点検で、この転送に次の 2 つが足りないと分かった。

- 送り元を確かめていない。ほかのサイトに仕込んだフォームや fetch から、ログイン中の人のブラウザに `POST /api/plans` を送らせる攻撃(CSRF)への備えは、Auth.js のクッキーが SameSite=Lax であることだけに頼っている。Lax なら、ほかのサイトからの POST にはクッキーが付かず 401 になるが、守りがクッキーの設定 1 つだけになる(OWASP は重ねて備えることを勧める)
- 本文の大きさに上限が無い。転送は本文を最後まで読んでからバックエンドに送り、バックエンドも 20MB の本文を最後まで解析して 422 を返した。道標を作る回数に上限を付けても(ADR 0038)、大きな本文を送り続ければメモリと CPU を使わせられる

## 検討した選択肢

送り元の確かめ方

1. ブラウザが付ける `Sec-Fetch-Site` を見て、same-origin か none でなければ断る。無ければ `Origin` と `Host` を照らす(Go の標準ライブラリの CrossOriginProtection と同じ形)
2. `Origin` を、設定した自分の URL(`AUTH_URL`)と照らす
3. 足さない(SameSite=Lax のクッキーに頼る)

## 決定

高橋さんが選んだ。送り元は 1。本文の上限の大きさは、入力の最大から決めた。

- `forwardToBackend`(Auth.js 以外の全ての Route Handler が使う)は、ログインを確かめる前に、GET、HEAD、OPTIONS 以外の要求の送り元を確かめる
  - `Sec-Fetch-Site` が same-origin か none なら通し、それ以外の値なら 403(「ほかのサイトからの要求は受け付けません」)
  - `Sec-Fetch-Site` が無ければ、`Origin` も無いなら通し(ブラウザでない。ログインのクッキーは別に要る)、`Origin` のホストが自分のホスト(前に置くプロキシの渡す `X-Forwarded-Host`、無ければ `Host`)と同じなら通し、違えば 403。ほかのサイトのページは `X-Forwarded-Host` を付けて送れない(付けると CORS の事前確認になり、このアプリは許していない)
- 本文は 64KB までにする。`Content-Length` が上限を超えていれば読まずに、無ければ読みながら上限を超えた時点で、本文を受け取るのを止めて 413(「要求の本文が大きすぎます」)
- 64KB は、道標の要求の本文の最大(クラスの選択 50 件、科目名とクラス記号はそれぞれ 100 字まで。日本語で約 30KB)の倍ほど
- 本番化では、前に置くプロキシでも本文の大きさを限る(この ADR の外)

## 理由

- `Sec-Fetch-Site` はブラウザが付け、ページのスクリプトから変えられない。自分の URL を設定しなくてよいので、手元と本番で変えるものが無い
- `Sec-Fetch-Site` を付けない古いブラウザでも、`Origin` と `Host` で同じ確かめができる
- 上限を Route Handler に置けば、バックエンドに届く前に断れ、前に置くプロキシの設定に関わらず守れる

## 受け入れたトレードオフ

- `Sec-Fetch-Site` も `Origin` も付けない古いブラウザからの要求は通す。そのときの守りは SameSite=Lax のクッキーだけになる
- `Origin` と照らすときは、前に置くプロキシが `X-Forwarded-Host` か元の `Host` を渡す必要がある。`Origin` の scheme は見ない(Go の CrossOriginProtection と同じ。http のページからの要求は HSTS で防ぐ)
- 本文を受け取るのを止めると、接続ごと切れて 413 が届かないことがある。正しい要求が 64KB を超えることは無い前提で、受け取りを止めるほうを取った
- 本文が 64KB を超える正しい要求は無い前提にしている。入力の上限を広げるときは、この上限も見直す

## 再検討する条件

- 本文の大きい要求(ファイルの取り込みなど)を足すとき
- ほかのサイトや別のサブドメインから呼ばせたいとき
