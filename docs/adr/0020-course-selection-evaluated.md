# 0020. 選び直しは gpt-5.4-nano で中心か土台かを付けて返し、重複は中心を優先して 1 つにまとめる

- ステータス: 承認
- 日付: 2026-10-16

## 文脈

ADR 0019 で、検索の上位 30 件から科目ごとに中心か土台かを付けて理由つきで返すと決め、LLM が同じ科目を 2 回返したらその答えを使わないとした。選び直しの評価のしかたと、選び直しの段のモデルは決めていなかった。

選び直しを評価データで動かしたところ、gpt-5.4-mini が通信・ネットワークエンジニアで「通信理論」を 2 回返し、答え全体が使えずに評価が止まった。0019 の決め方では、同じことが推薦でも起き、利用者がやり直すことになる。

## 検討した選択肢

同じ科目を 2 回返したとき

1. 1 つにまとめる。中心と土台で割れたら中心を、同じなら先に書かれた理由を使う
2. LLM を 1 回だけ呼び直す
3. 答えを使わずに止める(0019 のまま)

選び直しの段のモデル

1. 選び直しだけ gpt-5.4-nano、スキルを出す段は gpt-5.4-mini のまま(設定を分ける)
2. どちらも gpt-5.4-mini(設定は 1 つ)
3. どちらも gpt-5.4-nano

## 決定

重複は選択肢 1、モデルは選択肢 1。ADR 0019 のほかの決定は、ここに書き写して引き継ぐ。

選び直し

- LLM は、検索の上位 30 件(`SELECTION_CANDIDATE_LIMIT`、1〜100)の科目それぞれについて、中心・土台・関係なしのどれかを決め、中心と土台の科目だけを理由つきで返す。中心と土台の意味は判定者の指示文(`backend/eval/judge-prompt.md`)と同じ
- LLM に渡す抜粋の切り方は判定者に渡したものと同じにする。科目名、授業の概要と方法の先頭 450 字、到達目標の先頭 250 字、空でない各回のテーマをつないだ先頭 350 字。読むのは、その科目名のクラスのうち検索で最も近かったクラスのシラバス。区分と履修できる回生は渡さない
- 理由はシラバスの中身を自分の言葉で 80 字以内にまとめ、本文を写さないよう指示する。構造化出力の maxLength は文の途中で切るので使わない
- 返せる科目名は、構造化出力のスキーマの列挙で渡した 30 件に限る
- 同じ科目が 2 回返ったら 1 つにまとめる。中心と土台で割れたら中心を、同じなら先に書かれた理由を使う
- 結果の並びは中心、土台の順で、それぞれの中では検索の順位の順にする
- 選び直しのモデルは `SELECTION_MODEL`(初期値 gpt-5.4-nano)、スキルを出す段は `CHAT_MODEL`(初期値 gpt-5.4-mini、ADR 0018)

選び直しの評価

- `evaluate_selection` で、評価データの職業ごとに推薦と同じ処理を動かし、選んだ科目を判定の票と比べる。スキルの段の揺れを混ぜないよう、スキルは評価データの手書きのものを使う
- 判定の票から、科目を「期待(2 体以上が中心、または高橋さんが中心と決めた)」「土台(2 体以上が中心か土台、または高橋さんが土台と決めた)」「少数(1 体だけが挙げた)」「関係なし(どの判定者も挙げなかった)」に分ける
- 出すのは、中心と土台それぞれに選んだ科目の内訳、期待する科目のうち中心・土台に選んだ数と選ばなかった数・検索の上位に無かった数、中心の適合率(中心のうち期待の割合)、期待する科目を中心に選んだ割合、選んだ科目のうち関係なしの割合

## 理由

- 重複は、同じ科目について LLM が 1 つの答えの中で 2 回書いただけで、答えのほかの部分は使える。捨てると推薦全体が失敗し、呼び直すと時間と費用が倍になる。中心を優先するのは、2 回のうち 1 回でも仕事で直接使うと判断した科目を、時間割で後回しにしないため
- 選び直しの段で 2 つのモデルを 2 回ずつ評価した(10 職業、期待する科目 33 件)。どの指標でも nano が mini と同じか上回り、費用は約 4 分の 1 だった

| | gpt-5.4-mini | gpt-5.4-nano |
|---|---|---|
| 中心の適合率 | 64% / 64% | 65% / 69% |
| 期待する科目を中心に選んだ割合 | 64% / 64% | 73% / 67% |
| 選んだ科目のうち関係なし | 31% / 28% | 22% / 19% |
| 土台に選んだ数 | 149 / 143 | 93 / 103 |
| 期待する科目を選ばなかった数 | 1 / 0 | 0 / 0 |

- スキルを出す段は、曖昧な職業名で前提を書く決まり(ADR 0018)を守れる mini のままにした
- スキルを手書きに固定すると、評価の差が選び直しの段だけから来る

## 受け入れたトレードオフ

- 重複があったことは結果に残らない
- 設定が CHAT_MODEL と SELECTION_MODEL の 2 つになる
- どちらのモデルでも、中心に関係なしの科目はほぼ入らない一方、土台は 30 件中 9〜15 件と広く拾い、判定で関係なしの科目が 2 割前後混ざる。指示文の土台の定義(一部の回で触れる授業を含む)が広いためと見ている
- 評価はスキルを手書きに固定するので、スキルの段と選び直しの段を合わせた推薦全体の質は直接は測っていない
- クラスが複数ある科目では判定者と別のクラスのシラバスを読むことがあり、区分と回生も渡さないので、判定との食い違いには入力の差も混ざる

## 再検討する条件

- 土台に関係なしの科目が混ざることが時間割で問題になるとき(土台の定義を狭めた指示文を評価で比べる)
- 期待する科目の取りこぼしや、中心の適合率が下がるとき(N、抜粋の量、指示文を見直す)
- 1 回の費用や待ち時間が画面で許せないとき
