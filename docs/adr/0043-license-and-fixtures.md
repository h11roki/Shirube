# 0043. コードは MIT で公開し、取り込んだシラバスと時間割表の内容は対象外にして、テストの実ページは合成のページに置き換える

- ステータス: 承認
- 日付: 2026-10-22

## 文脈

リポジトリは GitHub で公開しているが LICENSE が無く、第三者が使える条件が決まっていない。取り込むシラバスと時間割表の内容は大学のもので、`backend/data/` は git 管理外にしているが、テストの fixture には実ページの HTML(5 件、教員名と本文を含む)をそのまま置いていた(ADR 0003 は実ページを保存して解析する方針で、テストにも実ページを使った)。本番の前の点検(テーマ B)で、ライセンスを明示することと、実ページを公開リポジトリに置かないことを決めた。

## 検討した選択肢

ライセンス

1. MIT。コードが対象で、取り込んだシラバスと時間割表の内容は対象外と README に書く
2. Apache-2.0。特許の条項が付くが、個人の小さなアプリには重い
3. ライセンス無し。第三者は使えない

テストの実ページ

1. 構造を写した合成のページに置き換え、生成スクリプトを fixture と並べて置く(時間割表の PDF の fixture と同じ形)
2. 実ページの文字を伏せ字にして構造だけ残す。大きさは変わらず、伏せた文がテストの期待値になって読めない
3. 実ページのまま。大学の文章と教員名が公開リポジトリに残る

## 決定

高橋さんが選んだ。ライセンスは 1(MIT)、実ページは 1(合成に置き換え)。

- LICENSE は MIT の標準の文で、著作権者はハンドル名 h11roki(本名を出さない方針、ADR 0042)
- README に、コードは MIT、取り込んだシラバスと時間割表の内容(`backend/data/`)と画面に出す引用は大学のもので対象外、と書く
- `backend/tests/fixtures/html/ritsumeikan/` の実ページ 5 件(詳細 4 件、検索結果 1 件)を消し、`make_pages.py` が作る合成のページ(架空の科目名、教員名、本文)に置き換える。合成のページは、解析が読む要素(見出し表、本文の欄、スケジュール表と成績評価の表、解析が読まない教科書と参考書の表、一覧の行と件数)を実ページと同じ入れ子(見出し表と本文の欄も `section.syllabus-section` の中)と属性で写し、段落の改行、注記の行、まとめた回、合併科目の「§」など、テストが確かめる癖を含める。生成物がスクリプトと一致するかをテストで確かめる
- 時間割表の PDF の fixture(`tests/fixtures/timetable/make_sample.py`)と、行の解析のテストに書いた行も、教員名を架空にする。授業コードと科目名は公開の事実なのでそのまま
- 科目名だけを使う単体テスト(検索の順位付けなど)は、科目名は公開の事実なのでそのまま

## 理由

- MIT は条件が短く、使う人が最も使いやすい。評価者が読む README にも一言で書ける
- 合成のページは小さく読め、テストの期待値を架空の値で書ける。伏せ字は構造を完全に残せるが、期待値が読めず、大きさも変わらない
- 生成スクリプトを並べて置くのは `tests/fixtures/timetable/make_sample.py` と同じ形

## 受け入れたトレードオフ

- 合成のページは実ページの Salesforce の外側(テーマの包み、スクリプト)を持たないので、外側の変化で解析が壊れることはこのテストでは分からない。実データの取り込みで確かめる
- 実ページの癖を新しく見つけたら、合成のページにも足す

## 再検討する条件

- 大学からシラバスの利用について求めがあったとき
- 他大学に広げて取得元が増えたとき(合成のページの作り方を取得元ごとに持つ)
