# 0093. 必修など先に入れる授業を一覧から選ばせ、学期とコマを決めて推薦より先に置き、推薦の候補からは除く

- ステータス: 承認
- 日付: 2026-11-05

## 文脈

- 道標は必修と卒業要件を見ない(ADR 0010。結果の画面にもそう断っている、ADR 0040)。学生の時間割には必修が先にあり、推薦の授業がそのコマと重なると、道標をそのまま履修の案にできない
- 入力の画面には職業名、回生、始める学期、学科で分かれたクラスの選択(ADR 0030)があり、「もう取った授業」は利用者ごとに覚えて候補から除く(ADR 0035)
- 高橋さんは、必修と卒業要件を扱わないのが学生にとって最大の穴で、全自動でなくても必修を自分で入れて避けられれば実用度が上がる、という案を選んだ

## 検討した選択肢

入れ方

1. 入力の画面で、その学科で残りの学期に開講される授業の一覧から検索して選ぶ。選んだ授業は学期とコマが決まった授業として先に置き、単位の上限にも数える
2. 授業名ではなく、学期ごとに空けたいコマ(曜日と時限)を指定する。小さい変更だが、何の授業か道標に出ず、単位も数えられない
3. 1 に加えて、「もう取った授業」と同じように利用者ごとに覚え、次に作るときも自動で入れる

推薦との関係

1. 推薦の候補から除く(もう取った授業と同じ決まり)
2. 候補に残し、推薦されたら理由つきの切符として出す

置き方

1. 学期ごとに、推薦の授業より先に置く
2. 推薦の授業と同じ列に並べて順に置く

選ぶ欄(入れ方 1 の画面)

1. 畳める欄の中に、名前で絞る入力と、名前、単位、開講の学期を添えたチェックボックスの一覧を置き、選んだ授業を上にまとめて外せるようにする
2. 授業名を打つと候補が浮かんで出て、選ぶと上の並びに足す入力(コンボボックス)
3. 絞る入力は置かず、残りの学期ごとに見出しを立ててチェックボックスを並べる

## 決定

高橋さんが、入れ方は 1 を選んだ。推薦との関係は 1、置き方は 1 にする。選ぶ欄は、高橋さんが 1 を選んだ。

- 入力の画面に「先に入れる授業」の欄を足す。`GET /api/v1/offered-courses?department=&grade=&term=` が、その学科で残りの学期に開講される授業(もう取った授業と同じページの授業は除く)を名前の順に、名前、単位、開講の学期とともに返す。学生は名前で絞って選ぶ。30 件まで
- `POST /api/v1/plans` に `fixed_courses`(授業名の並び)を足す。受け付けで、開講される授業の名前かを確かめ、違えば 422。クラスの選択は今まで通り `chosen_classes` で、先に入れる授業にも効く
- 道標の条件に `fixed_courses` を持つ。配置は、先に入れる授業を名前の順に全ての学期へ先に置いてから(その学期に開講され、クラスの選択と単位の上限とコマの重なりの決まりは推薦の授業と同じ)、推薦の授業を置く。春学期に置く通年の推薦の授業は、同じ回生の秋学期に先に入れた授業のコマも避ける。どの学期にも置けなければ「置けなかった授業」に並ぶ
- 推薦の候補からは、もう取った授業と同じ決まり(同じシラバスのページの授業ごと)で除く。残した推薦の鍵(ADR 0092)にもその分が入る
- 結果では、先に入れた授業の切符は `relevance: "fixed"` で理由は空、判子は「予定」。要約に「予定 n 科目」を足す。シラバスのリンクは、置いたクラスのページがあれば付ける(置けなかった授業には付けない)
- 保存の形は、条件の JSON に `fixed_courses`、結果の JSON は版 4(`roadmap.fixed` に名前とシラバスのページ)。マイグレーション 0012 が、保存してある条件と版 3 の結果に空の並びを足して版 4 にし、戻すときは先に入れた授業を道標から外して版 3 にする
- CLI の `plan create --fixed 授業名`(繰り返せる)
- 選ぶ欄は、クラスの選択と同じ畳める欄にし、要約に選んだ数を出す。名前で絞る入力は、全角と半角、大文字と小文字を区別せず、空白で区切った語を全て含む授業に絞り、当てはまる数を読み上げる。一覧は高さを区切ってスクロールさせ、30 件選んだら残りのチェックボックスを押せなくする。選んだ授業から外したら、欄の要約にフォーカスを戻す。回生や始める学期を変えて一覧に無くなった授業は、送らず要約にも数えず、その一覧で選び直したら選んだ並びから外す(学期を行き来して 30 件を超えないため)。回生や学期を変えて読み込むあいだは前の一覧を出したままにし、欄の開閉と絞り込みを保つ(読み込むあいだは送れない)。絞る入力で Enter を押しても道標は作らない。一覧を読めなければ、このまま送ると先に入れる授業なしで作ると断って読み直すボタンを出す。読み直しに失敗したときは、前に読んだ一覧のまま選べると断る
- 実装は 2 つに分ける。API、worker、CLI、保存の形、結果の画面の「予定」の切符を先に出し、入力の画面で一覧から選ぶ欄は次の PR で足す

## 理由

- 一覧から選べば授業名が道標に出て、コマと単位を正しく数えられる。コマだけ空ける案は、時間割帳に何の授業か出ない
- 候補から除くのは、学生がもう決めた授業に推薦の枠(候補 20 件)を使わないため。推薦されれば理由が読めるという利点はあるが、同じ授業が先に入れた授業と推薦の授業の 2 つの顔を持つ複雑さを避ける
- 先に置くのは、必修が推薦の都合で後の学期へずれないため。学期ごとに交互に置くと、春学期に置いた通年の推薦の授業が秋学期のコマを先に取り、秋学期だけの必修を押し出すので、先に入れる授業を全ての学期に置き切ってから推薦の授業を置く
- 選ぶ欄の 1 は、ふつうのチェックボックスと入力だけで、読み上げとキーボードの扱いをブラウザに任せられ、幅 320px でも崩れにくい。2 は画面が短く済むが、読み上げとキーボードの扱いを自分で書き、確かめることになる。3 は名前で絞れず、複数の学期に開講される授業が何度も出る
- 次回も覚える案は、必修は回生ごとに変わり、覚えた授業が次の年には要らなくなるので、今は入れない

## 受け入れたトレードオフ

- 必修かどうかはアプリは知らない。学生が選ぶ。必修の一覧の自動化は別の課題
- 先に入れる授業が多いと、推薦の授業は置けずに「置けなかった授業」に並ぶ
- 同じ名前が複数の学期に開講される授業は、最初に置ける学期に置く。学期は選べない
- 入力のたびに選び直す
- 一覧の単位は、同じ名前のクラスで単位が違えば、最初に開講されるクラス(同じ学期ならコードの小さい方)の単位を出す

## 再検討する条件

- 時間割表から必修の印が取れるようになったとき(自動で入れる)
- 先に入れる授業の学期を自分で決めたい、次回も覚えてほしいという声が出たとき
