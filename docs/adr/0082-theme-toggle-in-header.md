# 0082. 見た目の切り替えは、画面の隅に固定せずヘッダーに置く

- ステータス: 承認
- 日付: 2026-10-31

## 文脈

- ADR 0031 で、明るい見た目を既定にし、画面の隅の「ダークモード」のボタンで切り替えると決め、右下に固定して置いた
- 幅 375px でスクロールすると、このボタンが切符の文字や学期の見出しの上に重なる。README の画像を撮るときに見つかった
- 重なりを避けるため、フッターの下に余白を取り、html の下に scroll-padding(5rem、ADR 0056)を付けていたが、スクロールの途中の重なりは消えない。axe もボタンに覆われた文字の色の差を判定できず、e2e では手で測った文字の一覧に入れて通していた

## 検討した選択肢

1. ヘッダーのロゴの行の右端に置く
2. フッターに置く
3. 隅のまま、狭い幅では文字を消した丸いボタンにする

## 決定

高橋さんが 1 を選んだ。

- どの幅でも、ロゴの次、ナビの前に置き、CSS で並べ替えない。Tab の順がどの幅でも見た目の並びと同じになる(WCAG 2.4.3)。幅 1024px 未満では、ロゴの行の右端に置き、ナビを次の行に回す。1024px 以上では、ナビの左に並べる
  - ログイン中の名前は後から描くので、1 行に入るかを名前で決めると、名前が届いたときにナビが次の行に落ちて、ページ全体が下にずれる。名前が長くても 1 行に入る幅(1024px)まで、初めから 2 行にする
  - 初めはナビの右に置き、狭い幅でだけナビを次の行に回す並べ替えにしたが、レビューで、狭い幅の Tab の順が見た目と食い違い、640〜700px のログイン中は切り替えが 2 行目の左端に落ちると分かった。高橋さんが、広い幅でもナビの左に置くことを選んだ(ほかの案: 狭い幅でもナビの後ろに置いてヘッダーを 3 行にする、狭い幅だけ順の食い違いを受け入れる)
- 見た目は今の文字つきのスイッチのまま(「ダークモード」の文字と、押したかを伝える aria-pressed)。固定、影、半透明の背景はやめる。スイッチの色と位置は、描く前に当てる `data-theme` から CSS で決め(`globals.css` で `dark:` の変種を `data-theme` に結ぶ)、暗い見た目で読み込むたびに「切」から「入」へ滑らないようにする
- フッターの下の余白と、html の下の scroll-padding(ADR 0056)は、右下のボタンを避けるために取っていたのでやめる。画面の下に固定する「もう取った」のあとの知らせは、答えるとフォーカスを受け取り、フォーカスが離れると消えるので、フォーカスした部品を隠さない

## 理由

- どの幅でも、どの部品にも重ならない。どのページでも上の決まった場所で見つかる
- フッターは下まで下ろさないと見つからない。丸いボタンは重なる面積が減るだけで、スクロールの途中は切符の上を通り続ける

## 受け入れたトレードオフ

- ページの下の方を読んでいるときは、切り替えるのに上まで戻る
- 広い幅では、切り替えを右端に置くよくある形と違い、ナビの左に来る
- ヘッダーの部品が 1 つ増え、幅 1024px 未満ではヘッダーが 2 行になる。狭い幅で文字を大きくすると、ロゴの行に入りきらず、切り替えが次の行に回る

## 再検討する条件

- ヘッダーに部品が増え、狭い幅で 3 行を超えるとき
