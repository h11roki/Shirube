# 0052. 職業の読み取りを worker のメモリで覚えて使い回す

- ステータス: 承認
- 日付: 2026-10-23

## 文脈

同じ精度をより安く(ADR 0050、0051)の 3 つ目。多数決 3 回、候補 20 件、2 票目から 0.5 秒遅らせる今の既定で、1 件の費用は 1.01 円、選び直し 1 回の基準(0.81 円)との差は 0.2 円。そのうち職業の読み取り(gpt-5.4-mini)が約 0.15 円、時間は約 1.4 秒。

読み取りは揺れの元でもある。基準の実験では、読み取りを評価データの手書きのスキルに固定すると、選んだ科目のうち関係なしが 23% から 14%、同じ職業の回どうしの重なりが 0.45 から 0.65 になった(ADR 0048、README)。同じ職業名でも、読み取るたびにスキルと解釈が変わり、検索と選び直しの結果も変わる。

## 検討した選択肢

1. worker のメモリで覚える。DB に何も足さない。worker を再起動すると忘れる
2. DB に覚える。再起動しても残り、worker と CLI で共有できる。表とマイグレーションが要り、入力された職業名が持ち主と切り離されて残るので、退会(ADR 0041)とプライバシーポリシー(ADR 0042)の見直しも要る
3. 覚えない。読み取りの指示文を見直して揺れを減らす方に進む

## 決定

高橋さんが 1 を選んだ。

- application の `CachedOccupationAnalyzer` が読み取りのポートを包み、職業名ごとに読み取り(解釈、前提、スキル)を覚える。同じ職業名なら LLM を呼ばずに覚えた読み取りを返す
- 鍵は職業名そのもの(API が前後の空白を落としたもの)。全角と半角の違いなどは別の職業として読む。読み取りが失敗したときは覚えない
- 覚えるのは設定 `OCCUPATION_READING_CACHE_SIZE`(既定 500、0 なら覚えない)件までで、いっぱいなら一番長く使われていない職業から忘れる
- 覚えるのはプロセスの中だけ。指示文やモデルを変えるときは worker を起動し直すので(デプロイと同じ)、古い読み取りは残らない
- 道標の作成、recommend と plan の CLI、experiment が同じ組み立てを使う。experiment は 1 回の実験の中で覚えるので、2・3 回目の推薦は 1 回目の読み取りを使う

## 理由

- 同じ職業なら同じ読み取りになるので、作り直しても道標がそろう(揺れが減る)
- 同じ職業名が来るほど、読み取りの費用(約 0.15 円)と時間(約 1.4 秒)が減る
- DB に足さないので、退会やプライバシーポリシーに影響しない

## 受け入れたトレードオフ

- 最初の読み取りがよくないと、忘れるか再起動するまでその読み取りを使い続ける
- 効き方は同じ職業名がどれだけ来るかで決まる。experiment は職業ごとに 3 回流すので 3 回に 2 回は覚えた読み取りを使い、本番より効いて見える
- 退会しても、その人が入れた職業名の読み取りはメモリから消えない(持ち主と結び付けていない)。再起動か、ほかの職業に押し出されるまで残る
- worker を再起動すると忘れる

## 再検討する条件

- 本番で同じ職業名がどれだけ来るかが分かったとき(当たる割合が低ければ外す)
- worker を複数にするとき(覚えた読み取りを共有できない)
- 読み取りの指示文を直して揺れが小さくなったとき
