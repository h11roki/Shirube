# 0011. 認証は Auth.js の Google ログインとし、バックエンドへは署名付き JWT で本人性を渡す

- ステータス: 廃止(Superseded by 0027)
- 日付: 2026-10-14

## 文脈

最初のバージョンから Google ログインを入れ、利用者が自分の道標を保存・再表示できるようにする。バックエンドは Next.js の Route Handler 経由でのみ呼ばれる(ADR 0008)。

## 検討した選択肢

1. Auth.js(Next.js)で Google OAuth を行い、Route Handler から FastAPI へ短寿命の署名付き JWT を渡す
2. Amazon Cognito(Google を IdP として連携)
3. FastAPI 自身が OAuth を行い、セッションを発行する

## 決定

選択肢1。FastAPI は JWT の署名を検証して利用者を特定し、Plan の所有者チェック(認可)はバックエンドで行う。

## 理由

- ローカル開発が Google の OAuth クライアントだけで完結する
- AWS 側に追加サービスが要らない
- 認証(本人確認)はフロント側に置いても、認可とデータの所有はバックエンドに残る

## 受け入れたトレードオフ

- JWT の検証鍵をフロントとバックエンドで共有する
- Cognito と比べ、トークン検証が Next.js の実装に依存する
- メールアドレスを保存するため、プライバシーポリシーの掲示が要る

## 再検討する条件

- 利用者が増え、認証基盤の監査や多要素認証が必要になったとき(Cognito へ移行)
