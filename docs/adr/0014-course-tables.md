# 0014. 科目は取り込み元ごとの表に年度単位で入れ替え、入れ子は JSONB で持つ

- ステータス: 承認
- 日付: 2026-10-15

## 文脈

取り込み元は2系統(ADR 0012)。授業時間割表からは科目の所属と開講情報(`CourseSection`、1学科 624 行)、シラバスからは授業内容(`Syllabus`、530 ページ)を取り、授業コードで結合する。合併科目は1ページに複数のコードがぶら下がる(ADR 0013)。フェーズ4ではシラバスをセクション単位でチャンクにして埋め込みを pgvector に置く(ADR 0004、0005)。道標の生成は学科・入学年度・回生で候補を絞り、コマの衝突を避けて学期ごとに詰める(ADR 0007、0010)。

`CourseSection` と `Syllabus` は入れ子の値オブジェクトを持つ: コマ(曜日と時限の列)、配当(入学年度の範囲、回生、区分の列)、学科の集合、教員の列、授業回の列、成績評価の列。

## 検討した選択肢

表の切り方

1. 取り込み元ごとに表を分け、読むときに結合する
2. 結合済みの1表に時間割表の列とシラバス本文を並べる
3. 時間割表は JSONL のまま読み、シラバスだけ DB に入れる

入れ子の持ち方

1. JSONB 列
2. 全て子テーブルに正規化する
3. 絞り込みに使う配当と学科だけ子テーブルにする

年度と再取り込み

1. 全表に年度を持ち、「年度 × 取り込み元」単位で全削除と挿入を1トランザクションで行う
2. upsert で差分更新し、消えた行は別に削除する

## 決定

表は取り込み元ごと、入れ子は JSONB、再取り込みは「年度 × 取り込み元」単位の入れ替え。

| 表 | 主キー | 内容 |
|---|---|---|
| course_sections | (year, code) | 時間割表の1行。name、class_code、term、slots、departments、audiences、credits、instructors、room、registration、note |
| syllabi | (year, code) | シラバスの1ページ。code は主コード。見出し表の項目、本文の各項目、schedule_note、sessions、grading |
| syllabus_codes | (year, code) | ページに載る全てのコード(主コードと別名)とその科目名。syllabus_code で syllabi を指す |

時間割表の授業コードからシラバスを引くときは syllabus_codes を経由する。`Syllabus.aliases` は syllabus_codes の主コード以外の行から組み立てる。

slots、departments、audiences、instructors、sessions、grading は JSONB 列に、ドメインの値オブジェクトをそのままの形で入れる。列挙(Term、Weekday)は値の文字列で入れる。departments が None(全学科)のときは JSON の null ではなく SQL の NULL にし、`departments IS NULL` で引けるようにする。

取り込みは取り込み元ごとのユースケースが行い、どちらも年度の既存行を全て消してから挿入し、1トランザクションで確定する。

- `IngestTimetable`: その年度の時間割表 PDF を全てまとめて受け取り、`course_sections` を入れ替える。学科ごとに PDF が分かれても、年度の全ての PDF を一度に渡す。同じ授業コードの行が複数の PDF に同じ内容で現れたら1行にまとめ、内容が違えば止める
- `IngestSyllabi`: その年度の保存済みシラバスを全て受け取り、`syllabi` と `syllabus_codes` を入れ替える。時間割表に無い科目のページも入れる

どちらも、入力が空のとき、年度が指定と合わないとき(時間割表は配当の最も新しい入学年度、シラバスは見出し表の年度で見る)、1つの授業コードが2つのページに現れるときは、入れ替えずに止める。

## 理由

- 表が元データと1対1なので、片方の取り込み元だけ取り直しても他方に触れず、合併科目も syllabus_codes で自然に表せる。時間割表とシラバスの結合は読むときに授業コードで行う
- 入れ子は集約(CourseSection、Syllabus)の一部で、単独で問い合わせることがない。コマの衝突判定と配当の絞り込みは domain の純粋ロジックで行い、1学科 624 行、全学でも数万行なら全件を読んで絞れる。pgvector の検索で絞るときは候補の授業コードを `WHERE code IN` で渡せる
- JSONB でも `@>` の包含検索と GIN 索引で絞れるので、後から必要になっても表を増やさずに済む
- 年度単位の入れ替えは再実行が安全で、時間割表から消えた科目も反映される

## 受け入れたトレードオフ

- 読み出しに結合が要る
- 入れ子に外部キーや NOT NULL のような制約が効かない。形はドメインの型とマッピングのテストで守る
- 入れ替えで syllabi の行が消えるので、フェーズ4の埋め込みは本文のハッシュで再利用できる形にする
- 学科を足すときも、その年度の時間割表を全てまとめて取り込み直す。1学科の PDF だけ渡すと他学科の行が消える
- 時間割表の年度は、配当の最も新しい入学年度で確かめる。学科の時間割表には必ずその年度の入学者向けの科目があるので成り立つが、上回生向けだけの補遺や大学院の表は取り込めない
- syllabus_codes は主コードも position 0 の行として持つので、科目名が syllabi.title と重なる。全てのコードを1つの表で引くためで、どちらも同じ入れ替えで書く

## 再検討する条件

- 全学に広げて件数が数十万になり、全件読みが遅くなったとき(配当と学科を子テーブルにする)
- 入れ子の中身を単独で集計・表示する画面ができたとき
- 2つ目の学科の時間割表を入れたとき、同じ授業コードの行が学科ごとに違う内容(学科、教室、注記など)で載っていたとき。その時点の実データを見て、まとめ方を決める
