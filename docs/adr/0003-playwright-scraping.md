# 0003. シラバスは Playwright で描画後の HTML を保存してから解析する

- ステータス: 承認(User-Agent の連絡先は 0042 でリポジトリの URL だけにした)
- 日付: 2026-10-14

## 文脈

立命館大学のシラバス(学外向け)は Salesforce Experience Cloud 上にあり、全ページが JavaScript で描画される。素の HTTP で取得すると "Loading" しか返らない。robots.txt は全面許可、Crawl-delay なし、ログイン不要。sitemap.xml で科目詳細 URL を全件列挙できるが、学部・学科は URL から判別できない。

## 検討した選択肢

1. requests + BeautifulSoup: 描画前の HTML しか取れず不可
2. Playwright(ヘッドレス Chromium)で描画後の HTML を保存し、BeautifulSoup で解析する
3. Salesforce の内部 API(Aura)を直接呼ぶ
4. 手動で保存した HTML を解析する

## 決定

選択肢2。取得と解析を分け、取得した HTML は必ずローカルに保存する。解析のやり直しで再取得しない。

取得ポリシー:

- 1リクエストあたり 2〜3 秒以上空ける。単一スレッド
- 連絡先を含む User-Agent を名乗る
- 夜間など負荷の低い時間帯に実行する
- 教員のメールアドレスなど連絡先は保存しない

## 理由

- 人がブラウザで閲覧するのと同じ経路で、サイト内部の実装変更に強い
- 内部 API は非公開仕様で Salesforce のリリースごとに壊れ、利用規約上の説明もしにくい
- 手動保存は年度更新と他大学展開に耐えない

## 受け入れたトレードオフ

- 1ページ数秒かかる。1学科数百件なら数十分で済む
- Chromium に依存する。本番の Web コンテナには入れず、取り込みは手元か一時ジョブで実行する

## 再検討する条件

- 大学が公式のデータ提供や API を始めたとき
- サイトの構成変更で描画後の HTML から必要項目が取れなくなったとき
